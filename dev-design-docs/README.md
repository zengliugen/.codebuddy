# 引擎开发设计文档

> 本目录存放**引擎包在开发期产生的设计文档**（实施计划、契约快照、调研结论等）。
> 读者是**维护引擎本身的人**，不是装了某个包的项目。

## 一、入库规则（重要）

**只有本 README 入库**。除 README 外的全部内容由 `.gitignore` 忽略：

```gitignore
/dev-design-docs/*
!/dev-design-docs/README.md
```

规则含义：目录内一级条目全忽略，仅放行 README。`dev-design-docs/<包名>/` 下的文档
**不会进入版本库**，只存在于本地工作区。

**为什么这样设计**：

| 理由 | 说明 |
|------|------|
| 开发期产物，非交付物 | 计划文档在实施完成后即失去价值；契约快照随引擎演进频繁改写，入库会产生大量无意义 diff |
| 不随引擎分发 | `scripts/pack_install.py` 只物化 `rules`/`skills`/`agents` 三类组件，文档本就不会到消费项目 |
| 避免永久脏工作区 | 若放在 `lib/<pack>/docs/` 且不提交，子模块指针会长期显示 dirty，干扰状态判断 |

> **注意**：因文档不入库，**换机器或重新 clone 后这些文档不存在**。
> 需跨机器共享或长期保留的结论，必须落到包的组件文档（`rules/` / `skills/references/`）中，
> 而不是留在这里。
>
> **备份提示**：本目录内容不会随仓库分发，`git clean -fdx` 或更换工作区会静默丢失。
> 重要的本地文档请自行备份，或另存到版本库之外的位置。

## 二、目录布局

按包名分目录，与 `lib/<pack>/` 同构：

```
dev-design-docs/
└── <包名>/
    └── <文档>.md
```

本 README **不登记具体文档清单**——那些文件不入库，列出来对其他检出者全是死链。
需要了解某包有哪些本地文档，直接查看对应子目录。

## 三、文档约定

1. 新包的文档放 `dev-design-docs/<包名>/`，目录随需创建，无需改 `.gitignore`。
2. **生命周期一律为「临时」**：服务于包开发，**包开发完成后即失去价值**，随整个目录一并归档或删除。
   文档头须标注 `生命周期：临时` 并写明终止条件。
   > 不设「长期维护」档：本目录内容都不入库，宣称长期保留与实际不符；
   > 开发完成后仍需保留的结论，应移入包的组件文档（`rules/`、`skills/references/`）。
3. 文档语言为简体中文、编码 UTF-8 无 BOM（遵循 `rules/core/language/`）。
4. 文档中引用其他包的组件不受限制——本目录内容不入库，不参与引擎校验项 7
   （`check_manifest.py` 的跨包引用检查）。
