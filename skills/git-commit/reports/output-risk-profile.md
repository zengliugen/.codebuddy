# 输出风险画像

## 风险矩阵

| 风险类别 | 严重度 | 概率 | 影响 | 缓解措施 |
|---------|--------|------|------|---------|
| 提交摘要质量问题 | 中 | 中 | 历史可追溯性受损 | 提交摘要格式规范 + 检查清单 |
| .gitignore 检查遗漏 | 高 | 低 | 敏感文件被提交到仓库 | 四步检查流程 + 强制交叉比对 |
| 用户授权缺失 | 高 | 低 | 未授权代码被推送 | AskUserQuestion 强制确认 |
| 提交与推送未分离 | 高 | 低 | 未审查提交被推送 | 强制分离规则 + 禁止链式命令 |
| 多模块变更未拆分 | 中 | 中 | 提交粒度不清晰 | 拆分规则 + 多模块变更示例 |
| 边界情况未处理 | 中 | 中 | 空提交/冲突/hook 失败导致流程中断 | 边界情况处理指南 |
| Scope 推断错误 | 低 | 中 | 提交范围标注不准确 | 四级优先级 scope 提取规则 |
| 审查遗漏配置的文件类型变更 | 中 | 低 | 未审查的代码质量问题进入仓库 | 阶段五 H1 首步骤按项目侧 project-config.md §2 文件模式筛选 + 检查清单 |
| error 问题被静默提交 | 高 | 低 | 已知缺陷绕过审查进入提交 | 阻塞规则 + AskUserQuestion 强制授权 |
| 审查误报阻塞提交 | 中 | 中 | 工具启发式误报导致提交流程中断 | 疑似误报标注 + 用户可授权忽略 |
| H1 步骤顺序漂移 | 中 | 低 | 钩子步骤增删或次序变化未生效 | H1 顺序唯一来源为项目侧 project-config.md §3，SKILL.md 只留指针不列步骤 |
| 多会话并发 git 写操作冲突 | 高 | 中 | 暂存区污染（混入他会话文件）、提交被回滚 | VCS 互斥锁（`vcs_lock.py`，逐笔加锁：获授权后获取、锁内 add→校验→commit、提交后立即释放）+ 提交前暂存区校验 |

## 输出质量维度

### 提交摘要质量

可能的问题：
- subject 超过 50 字符
- subject 以句号结尾
- scope 缺失或不准确
- type 选择不当（如用 `feat` 表示文档变更）
- 多个独立功能堆砌在一条摘要中

防护措施：
- 提交摘要格式规范（`references/commit-spec.md`）
- 在生成阶段进行格式校验
- 展示提交计划让用户审查

### 安全检查完整性

可能的问题：
- 未读取最新 .gitignore
- 使用记忆中的忽略规则而非文件内容
- 未执行 `git ls-files --cached --ignored --exclude-standard`

防护措施：
- 四步检查流程（cat + diff + ls-files + status）
- 明确禁止使用记忆规则
- 检查清单逐项确认

### 用户交互质量

可能的问题：
- 以纯文本提问代替 AskUserQuestion
- 依赖对话上下文推断用户意图
- 提交后自动推送

防护措施：
- AskUserQuestion 强制规则
- 提交与推送强制分离
- 用户主动发起原则

## 已知局限性

1. **对话上下文可能不完整**：对话摘要可能遗漏部分修改，导致 scope 推断偏差。
2. **Git diff 推断意图可能不准确**：仅通过 diff 内容推断提交类型和 scope 存在误判风险。
3. **Scope 提取规则覆盖不全**：项目结构新增路径时可能无法精确匹配。
4. **subject 自动化校验读取配置**：`scripts/validate_commit_subject.py` 读取项目侧 `skills/git-commit/config.json`（索引 `git_commit.config`）校验 type 枚举、subject/scope 长度、subject 语言、无句号结尾；**配置为唯一来源**，缺失/字段非法时报错退出（退出码 3），不回退默认值。scope 的业务准确性（模块名是否正确）仍需人工判断。
5. **配置缺失即报错**：`git-commit/config.json` 缺失、损坏或字段非法时脚本报错退出（退出码 3），不再静默回退默认值——避免「配置改了却不生效」被掩盖。
