# 输出风险画像

## 风险矩阵

| 风险类别 | 严重度 | 概率 | 影响 | 缓解措施 |
|---------|--------|------|------|---------|
| 无依据判错（臆测业务逻辑） | 高 | 中 | 误导用户修改正确的代码 | Agent 安全约束禁止臆测 + 问题必须附证据与行号 |
| 误报（启发式误判） | 中 | 高 | 用户被无关问题干扰，审查信任度下降 | 区分 error/warning/info 严重级别 + 疑似问题单独标注 |
| 修复越界（修改报告之外代码） | 高 | 低 | 引入新缺陷 | 修复模式前置授权 + 只改报告中明确列出的问题 |
| 生成代码被审查 | 中 | 低 | 浪费时间与噪声 | 豁免 Generated/、Gen/ 与 auto-generated 文件 |
| 审查遗漏（漏检真实问题） | 中 | 中 | 问题流入提交 | 五维审查全覆盖 + 工具辅助（Roslyn 注释检查 + dotnet format 格式检查） |
| 报告格式不合规 | 低 | 中 | 用户难以定位问题 | report-spec 强制报告结构 + check_logs 命名规范 |

## 输出质量维度

### 审查报告质量

可能的问题：
- 问题描述无行号、无证据，纯主观判断
- 将推测性结论标注为确定性结论（error/warning 而非 info）
- 维度分布缺失或统计错误
- 疑似问题与确认问题混在一起，未区分

防护措施：
- Agent 安全约束："禁止臆测"、"无法确认的问题标 info 并注明疑似"
- 报告结构（report-spec）：概览 / 问题列表（行号+级别+维度+规则+建议）/ 统计 / 维度分布 / 疑似问题
- 对话摘要与完整报告分离，关键结论有据可查

### 修复模式质量

可能的问题：
- 未经授权自动修改代码
- 修复范围超出报告列出问题
- 修复引入新问题或修改无关代码

防护措施：
- 修复前置条件：用户明确指令 + AskUserQuestion 确认范围
- 修复边界：仅修复报告中列出的问题，修复后重新运行审查验证
- 修复前后统计对比写入报告"修复验证"章节

### 工具依赖质量

可能的问题：
- Roslyn 工具不可用时降级为手工检查，可能漏检注释问题
- 工具构建耗时（首次 dotnet publish）导致用户等待

防护措施：
- 降级路径明确："手工审查并在报告中注明注释合规维度为手工检查"
- 首次构建等待有说明，构建结果哈希缓存避免重复构建

## 已知局限性

1. **静态分析无法完全理解业务语义**：架构与性能维度的部分判定依赖代码证据 + 项目规则，复杂业务逻辑可能误判，已通过"疑似"标注缓解。
2. **目录模式（模式 C）全量扫描耗时**：大型目录逐文件审查可能超过单次响应预算，需分批处理。
3. **Git 变更审查依赖 diff 完整性**：未跟踪新文件需显式读取，若遗漏可能漏检。
