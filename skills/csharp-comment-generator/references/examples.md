# 使用示例

## 示例 1：为 C# 文件添加注释

用户："为 `MyClass.cs` 添加注释"

Agent 流程：
1. 读取规则目录（`.codebuddy/rules/csharp-comment/`）下的全部规则文件
2. 读取并分析 `MyClass.cs` 的代码结构
3. 识别所有需要注释的成员
4. 为缺失注释的成员生成 XML 文档注释
5. 为方法体内部的关键逻辑添加行内注释
6. 修正不合规的现有注释
7. 添加文件头注释
8. 使用文件编辑工具修改文件
9. 输出汇总报告

## 示例 2：检查并修正注释

用户："检查 `MyLogic.cs` 的注释是否符合项目规范"

Agent 流程：
1. 读取规则目录（`.codebuddy/rules/csharp-comment/`）下的全部规则文件
2. 读取并分析 `MyLogic.cs` 的代码结构和现有注释
3. 按修正规则四维度检查已有注释质量（书写正确性、描述清晰度、描述完整性、语义一致性）
4. 识别不合规的注释（格式错误、内容缺失、书写错误、描述不清等）
5. 逐项修正不合规注释
6. 补充缺失的行内注释
7. 使用文件编辑工具修改文件
8. 输出问题清单和修正报告

## 示例 3：补全缺失的注释

用户："按照项目注释规范补全 `MyManager.cs` 缺失的注释"

## 示例 4：部分处理

用户："只为 `MyClass.cs` 中 `SwitchState` 方法相关的代码添加注释"

Agent 流程：
1. 读取规则目录（`.codebuddy/rules/csharp-comment/`）下的全部规则文件
2. 读取 `MyClass.cs`，定位 `SwitchState` 方法及其直接关联成员
3. 仅为用户指定的方法及相关成员生成文档注释和行内注释
4. 跳过文件中的其他成员，不做修改
5. 输出仅涉及修改范围的汇总报告

## 示例 5：拒绝非 C# 文件

用户："为 `utils.ts` 添加注释"

Agent 流程：
1. 确认文件扩展名 → `.ts`（非 `.cs`）
2. 告知用户：本 Agent 仅支持 C# 代码文件（`.cs`），不处理 TypeScript 文件

## 示例 6：根据 checker 报告修复（闭环工作流）

用户："根据 `check_logs/2026年08月01日_MyClass_cs_e0w1_xxxx.json` 修复注释问题"

Agent 流程：
1. 进入报告驱动修复模式（模式 B），跳过规则文件读取
2. 解析 JSON 报告，提取 Issue 列表
3. 按文件分组：仅 `MyClass.cs` 一个文件
4. 读取 `MyClass.cs`
5. 按行号从末尾向前逐项修复：
   - 行 54 [warning] `OnEndSwitchAsync` 缺 `<returns>` → 分析方法签名，生成 `<returns>` 标签
   - 行 120 [error] `SwitchState` 缺文档注释 → 分析方法体，生成完整 `<summary>` + `<param>` 文档注释块
6. 保存文件
7. 输出修复报告：总问题 N，已修复 M，需人工处理 K

用户："再用 checker 验证一遍"
→ 运行 checker，确认问题已清零。
