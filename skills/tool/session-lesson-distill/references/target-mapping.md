# 落点判定规则

本文件定义一条经验应当写入哪个载体、哪个文件、哪个位置。判定顺序固定：先选载体，再选文件，最后定位并查重。

## 1. 载体选择：技能还是规则

| 经验性质 | 载体 | 理由 |
|---------|------|------|
| 某个技能的执行流程、顺序、门禁、参数 | 技能 | 只在该技能被调用时才有意义 |
| 某个技能对工具/框架的用法细节 | 技能 | 属于该技能的实现知识 |
| 跨技能的项目规范（命名、注释、语言、目录组织） | 规则 | 多个技能都需要遵循 |
| 约束「所有代码/所有文件」的强制或禁止条款 | 规则 | 需要始终生效或按路径注入 |
| 项目结构、架构、依赖关系的事实性说明 | 规则（`project-guide`） | 属于项目背景知识 |

边界判定：

- 若一条经验只在执行某技能时才需要被读到 → 技能。
- 若一条经验在任何涉及某类文件的操作中都需要被读到 → 规则。
- 若两边都成立 → 写入规则，并在技能中引用规则，避免同一内容维护两份。

## 2. 技能内的文件选择

技能遵循「入口精简、细节下沉」的项目约定：

| 内容形态 | 落点 | 说明 |
|---------|------|------|
| 执行步骤、阶段划分、检查清单 | `SKILL.md` | 入口，保持可快速扫读 |
| 判定标准、阈值、决策表、示例 | `references/*.md` | 细节下沉，由 `SKILL.md` 的参考文献表索引 |
| 可确定性执行的扫描、校验、解析 | `scripts/*.py` | 用脚本替代重复人工判断 |
| 输入/输出/排除契约 | `agents/interface.yaml` | 契约变更时同步 |
| 触发边界案例 | `evals/trigger/*.md` | 新增易混淆的触发场景时补充 |

**约束**：不因一条经验就新建 `references/*.md`。优先并入既有的同类 reference；确无同类且内容足以独立成篇时才新建，并在 `SKILL.md` 参考文献表登记一行。

## 3. 规则内的文件选择

规则遵循「入口 + 子规则」模式：

| 内容形态 | 落点 | 说明 |
|---------|------|------|
| 强制入口条款、子规则路由表、加载机制说明 | `RULE.mdc` | `alwaysApply: true`，始终生效 |
| 具体规范细则、判定标准、示例 | `*-spec.mdc` 等子规则 | `alwaysApply: false`，按需加载 |
| 适用范围、豁免与例外 | 既有范围类子规则 | 优先并入，不新建 |

**约束**：不因一条经验就新建子规则文件。子规则拆分与合并属于 `rule-consolidation` 技能的职责；本技能只在既有子规则内补充条款。

## 4. 入口同步

写入细节文件后，必须检查入口是否需要同步：

| 写入位置 | 需检查的入口 | 同步条件 |
|---------|-------------|---------|
| 技能 `references/*.md` | `SKILL.md` 的参考文献表 | 新建 reference 时必须登记；既有 reference 的内容扩充无需改动 |
| 技能 `scripts/*.py` | `SKILL.md` 的参考文献表 | 新建脚本时必须登记 |
| 规则子规则 | `RULE.mdc` 的子规则路由表 | 新建子规则时必须登记；既有子规则补充条款无需改动 |
| 技能 `agents/interface.yaml` | —— | 输入/输出/排除契约变化时同步 |

## 5. 去重

写入前必须读取目标文件全文，按三种情况处置：

| 情况 | 判定 | 动作 |
|------|------|------|
| 已存在等价条款 | 语义等价，措辞不同 | 标记「已存在，跳过」，不写入 |
| 已存在相关但更泛的条款 | 覆盖范围更广，缺本次的具体约束 | 动作标为「补充」，在既有条款处扩展，不新起一段 |
| 不存在 | —— | 动作标为「新增」 |

**禁止**：因措辞不同就重复写入；因条目更细就在同一文件里另起一节复述既有内容。

## 6. 一条经验的多个落点

一条经验可能需要同时落到多处（例如既改技能流程、又在规则中登记约定）。处理原则：

1. **区分主次**：确定主落点（承载完整说明）与从落点（只保留指针或最小必要条款）。
2. **避免重复维护**：同一段完整说明只写一处，另一处用引用替代（如「详见 `.codebuddy/rules/.../xxx.mdc`」）。
3. **报告中逐条列出**：落点映射段为每条经验列出全部落点及各自动作。

## 7. 判定流程

```text
经验条目
  ├─ 只在某技能执行时需要？ ── 是 → 技能
  │                                 ├─ 是执行步骤/清单？ → SKILL.md
  │                                 ├─ 是判定标准/示例？ → references/*.md（优先并入既有）
  │                                 └─ 是可确定性执行？ → scripts/*.py
  └─ 否，属跨技能规范/项目事实？ ───→ 规则
                                    ├─ 是强制/禁止条款？ → RULE.mdc
                                    └─ 是细则/示例？     → 既有子规则（不新建）
  ↓
读取目标文件查重 → 新增 / 补充 / 已存在跳过
  ↓
检查入口（参考文献表 / 子规则路由表）是否需同步
```
