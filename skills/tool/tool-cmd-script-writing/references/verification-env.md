# 验证脚本运行的环境要求

本文件说明 cmd-script-writing 技能"阶段三：验证"对运行环境的要求，避免在错误环境下误判验证结果。

## 核心要求：必须在真实 Windows CMD 中运行验证

批处理脚本的行为由 Windows CMD（`cmd.exe`）解析器决定。**验证必须使用真实 CMD 环境**，不得使用以下替代环境：

| 环境 | 是否可用于验证 | 原因 |
|------|--------------|------|
| 真实 `cmd.exe`（Windows 终端 / CMD 窗口） | **是** | 与生产环境一致，`chcp 65001`、行尾解析、`goto` 行为均真实 |
| Git Bash 运行 `.cmd`/`.bat` | **否（会失真）** | Git Bash 的 `winpty`/`msys` 层会改写终端行为，换行、代码页、`%~dp0` 展开均可能与真实 CMD 不一致，乱码与 `is not recognized` 现象可能不出现或假出现 |
| PowerShell 调用 `.cmd` | **谨慎** | PowerShell 调用批处理会经过宿主层，输出编码与错误处理与直接 CMD 不同；仅可作为补充冒烟，不能替代 CMD 验证 |
| WSL / Linux shell | **否** | 完全不同的解析器 |

## 验证前的环境检查清单

1. 确认运行环境为 `cmd.exe`（Windows 原生终端）。
2. 确认脚本文件编码为 **UTF-8 无 BOM**、行尾为 **CRLF**（`SKILL.md` 阶段三已含校验命令）。
3. 脚本若含 `chcp 65001`，确认终端支持 UTF-8 代码页。
4. 若脚本涉及破坏性命令（`del`/`rd`/覆盖写），先在安全副本上验证，确认行为后再在真实目标上运行（与 `SKILL.md` 阶段三"运行前先人工检查"呼应）。

## 验证结果判定

- **乱码**：真实 CMD 下 `echo 中文` 应正常显示；若出现 `锟斤拷` 等乱码，说明编码/代码页配置问题。
- **`is not recognized`**：真实 CMD 下若行尾为中文/全角标点，应能复现该报错；`--fix` 修复后报错消失。
- **`goto` 作用域**：真实 CMD 下验证括号块内 `goto` 的变量展开行为。

> 在非真实 CMD 环境下"验证通过"**不构成有效证据**，必须切换至真实 CMD 复验。
