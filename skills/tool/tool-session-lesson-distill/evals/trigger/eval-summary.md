# 触发评估摘要

## 测试范围

|------|--------|-----------|

## 触发设计

本技能有两条触发路径，`description` 中均已显式覆盖：

1. **用户主动调用**：显式要求沉淀本次会话经验（"把这次的经验固化一下"、"沉淀到技能里"、"/session-lesson-distill"）。
2. **主动触发信号**：会话中出现可复用经验信号时由智能体主动建议或触发，信号包括——
   - 用户纠正了做法；
   - 同一类问题重复出现（踩坑两次以上）；
   - 发现技能或规则文档与实际实现不符；
   - 复杂多阶段任务收尾。

## 关键路由边界

最容易被误路由的边界场景：

1. **沉淀 vs 创建技能**：涉及"技能"一词但意图是新建技能或重构技能结构时，应走 `yao-meta-skill`，本技能不承接。
2. **沉淀 vs 规则重组**：规则文件的拆分与合并走 `tool-rule-consolidation`；本技能只在既有子规则内补充条款，不新建、不拆分、不合并规则文件。
3. **写回规范 vs 审查代码**：本技能写回的对象是技能与规则文件，不审查也不修改 `.cs` 代码。
4. **有无会话上下文**：全新会话首轮的知识问答、翻译、一次性文档撰写没有可沉淀的会话经验，不应触发。
5. **本次经验 vs 历史存量**：清理与本次会话无关的历史遗留问题不属于本技能职责。

## 评估方法

- **人工审查**：逐个验证每个案例的输入是否能被 `description` 正确路由。
- **盲测**：打乱案例顺序，由独立评审者判断是否应触发，避免受案例分组影响。
- **对抗测试**：构造同时含"技能"与"沉淀"字样但实际属于相邻技能职责的输入（如"把这次经验沉淀成一个新技能"），验证排除逻辑可靠。

## 备注

- 主动触发路径依赖智能体对"可复用经验信号"的判断，属于语义判断而非关键词匹配；上表第 7-14 条用于回归验证该判断的稳定性。
- 案例 20-22 覆盖同目录其他技能的职责，用于验证不会因"会话收尾/总结经验"类措辞而误路由。
