# rule-consolidation 触发评估用例集

本文件定义 `tool-rule-consolidation` 技能的触发评估用例，按三桶分类：**应触发**（Should Trigger）、**不应触发**（Should Not Trigger）、**相近邻居**（Near Neighbor）。判定依据为 `SKILL.md` frontmatter 的 `description` 与 `agents/interface.yaml` 的契约。

## 一、应触发（Should Trigger）

验证召回率：这类请求应路由到本技能。

| 编号 | 用户 Prompt | 期望处理 |
|------|------------|---------|
| ST-01 | 规则内容太多，拆分子规则 | 拆分 |
| ST-02 | 按入口+子规则模式调整规则结构 | 拆分 |
| ST-03 | 规则拆得太细，合并一下 | 合并 |
| ST-04 | 子规则太小可以放一起 | 合并 |
| ST-05 | 评估是否过度拆分 | 评估（仅报告） |
| ST-06 | 规则结构是否符合项目模式 | 评估（仅报告） |
| ST-07 | 把 language 规则的子规则合并 | 合并（指定目标） |

## 二、不应触发（Should Not Trigger）

验证精确率：这类请求明显在技能边界外。

| 编号 | 用户 Prompt | 应路由到 |
|------|------------|---------|
| SN-01 | 帮我写一个提交摘要 | `vcs-git-commit` |
| SN-02 | 审查这次 C# 变更 | `csharp-code-review` |
| SN-03 | 为这个 .cs 文件补注释 | `csharp-comment-generator` |
| SN-04 | 创建一条全新的规则（从零开始） | 不触发（new_rule 被排除） |
| SN-05 | 修改规则里的审查维度内容 | 不触发（rule_logic 语义变更被排除） |

## 三、相近邻居（Near Neighbor）

验证边界：看似相似但应正确分流的请求。

| 编号 | 用户 Prompt | 潜在误路由 | 正确路由 |
|------|------------|-----------|---------|
| NN-01 | 整理一下 .codebuddy 的规则文件 | 可能是拆分/合并 | 本技能评估并执行重组 |
| NN-02 | 看看规则结构合不合理 | 可能是通用咨询 | 本技能评估模式（仅报告不修改） |
| NN-03 | 技能文件太多要拆分 | 可能是规则拆分 | `skills/` 文件不归本技能处理（skill_files 排除），提示用户范围 |
| NN-04 | 规则内容有矛盾，帮我改 | 可能是重组 | 内容语义修正属 rule_logic 排除，仅提示不执行 |

## 判定标准

- **召回率**：`ST-01` 至 `ST-07` 全部路由到本技能。
- **精确率**：`SN-01` 至 `SN-05` 均不路由到本技能。
- **边界安全**：`NN-01` 至 `NN-04` 正确分流，不越权处理技能文件或语义变更。
