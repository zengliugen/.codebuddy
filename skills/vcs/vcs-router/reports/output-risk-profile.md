# 输出风险画像

## 风险矩阵

| 风险类别 | 严重度 | 概率 | 影响 | 缓解措施 |
|---------|--------|------|------|---------|
| VCS 类型误判（Git 仓库漏检） | 高 | 低 | 路由失败或判定 none | 命令确认 + `.git` 目录兜底 |
| 缓存误导路由 | 中 | 低 | 目录切换后使用过期缓存 | 缓存路径一致 + 10 分钟超时 + `none` 不写缓存 |
| 路由到不存在的目标技能 | 中 | 低 | 提示不友好/无操作 | `target_exists` 校验 + 提示"操作暂未支持" |
| 非版本控制上下文误路由 | 中 | 中 | 无关请求进入提交流程 | description 明确排除"提交表单/提交报告" |
| VCS 锁误用（越权/漏释放） | 高 | 低 | 并发写操作污染 | O_EXCL 原子创建 + session 归属校验 + stale 接管 |

## 输出质量维度

### 路由结果质量

可能的问题：
- 路由结果 JSON 字段缺失或类型错误
- `target_exists` 判断与技能实际存在不一致
- 用户指定 VCS 类型被忽略

防护措施：
- `build_result` 统一组装 8 个字段（`route_vcs.py:172-184`）
- `target_exists` 检查 `skills/<目标>/SKILL.md` 存在性
- 用户显式指定类型时跳过检测与缓存

### 检测准确性

可能的问题：
- Git 仓库子目录漏检
- `.git` 目录兜底与命令结果冲突

防护措施：
- git：命令 + `.git` 目录兜底（`git rev-parse` 在仓库任意子目录均返回 true）

### 缓存行为

可能的问题：
- 目录切换后缓存误命中
- 缓存过期未触发重新检测
- `none` 结果写入缓存导致后续误导

防护措施：
- 缓存必须三条件全满足才命中（路径一致 + 类型合法 + 未超时）
- `none` 不写缓存

## 已知局限性

1. **仅支持 Git**：检测只识别 Git 仓库，非 Git 目录会判定为 `none` 并提示不支持。
2. **缓存为进程内单文件**：多项目共享同一 `.codebuddy`（目录链接）时缓存按绝对路径隔离，天然安全；但手动复制配置到新位置后旧缓存可能残留，需 `--refresh` 或清理。
3. **路由仅覆盖 commit/merge 两类操作**：revert/stash/branch 等未来操作需新增目标技能目录。
