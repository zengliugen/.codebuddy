## 测试策略

本能力是纯脚本改造，无自动化测试（该脚本本身无单元测试，见 `references/guide.md` 的「已知限制」）。
验证方式为**实际运行七个模式并核对输出与副作用**，覆盖「域隔离」「配置迁移」「保护条件不回退」三类。

| 被测行为 | 为什么必须覆盖 | 对应用例 |
|---|---|---|
| 项目域在迁移后行为不变 | 迁移配置是本次改动风险最高处：路径若被错解，已有文档会与总览表脱钩 | 迁移前后 `audit` 结果一致（均 0/0/0） |
| 旧 v1 配置必须显式失败 | 「配置写了但没生效」是这套工具最怕的失效形态，必须确认没有静默回退 | 临时换回 v1 配置，期望退出码 3 |
| 引擎域可从零初始化 | 新增的第二棵树必须能独立建成，且用引擎域专属的总览模板 | `--scope engine init` 产出四份说明，其中根 README 来自 `README.engine.md` |
| 两域文档树互不干扰 | 域隔离是本能力的核心承诺；一旦共用目录，两套总览表会互相踩 | 两域各自 `audit`，引擎域的探索记录不出现在项目域体检里 |
| `new` 的三条保护在新域上仍生效 | 换路径来源不应削弱任何保护条件 | 缺 `--from-explore`、重名、保留目录名三种输入均应拒绝 |
| `--scope` 前置与后置等价 | 子命令注册 `--scope` 时若默认值写 `None`，会静默覆盖顶层已解析值 | `--scope engine audit` 与 `audit --scope engine` 输出一致 |
| 未知域名给出可用域清单 | 拼错域名时若只报「未知域」，用户无法知道该填什么 | `--scope nope audit` 应列出 `engine、project` |

**刻意不测的行为**：

| 行为 | 不测的原因 |
|---|---|
| 文档内容是否正确 | 属评审，机械检查无法判断论证是否站得住 |
| 引擎域能力名前缀是否合规 | 需要权威包清单，脚本刻意不依赖安装形态（见设计文档「未解问题」） |

## 验收记录

| 日期 | 测试根 | 用例数 | 结论 | 环境 |
|---|---|---|---|---|
| 2026-11-10 | 手工运行 `devflow_guard.py` 七个模式（无自动化测试根） | 9 | 通过 | Windows 10 Pro / Python 3 / 项目根 `Program/Client` |

九项对应上表的七个行为，外加「配置不得含 `base_root`」与「各域文档根解析后须不同」两条新增校验
（通过推演确认拦截路径：前者在 `load_config` 里对顶层与域覆盖层各查一次，后者在
`_validate_scope_docs_root` 里比对解析结果）。

关键输出摘要：

```text
# 项目域（迁移后，与迁移前完全一致）
域：project（base=project，文档根：.codebuddy.project/docs/devflow）
结论：错误 0，警告 0，提示 0 / exit=0

# 旧 v1 配置
配置不可用：配置缺少必需键：default_scope / exit=3

# 引擎域
已初始化文档结构（域 engine）：.codebuddy/dev-docs / exit=0
域：engine（base=engine，文档根：.codebuddy/dev-docs）
结论：错误 0，警告 0，提示 0 / exit=0

# --scope 后置
$ audit --scope engine → 域：engine / exit=0

# 未知域
配置不可用：未知的域：'nope' / 可用域：engine、project / exit=3

# new 的保护
缺 --from-explore → 建立能力文档前必须先确认需求 / exit=2
重名 → 能力已存在于总览表 / exit=2
保留目录名(archive) → 能力名与保留目录同名 / exit=2
```

> **必须写明依据的是哪个测试根。** 本次无自动化测试根，验证依据为手工运行输出；
> 因此「体检全绿」只能证明契约成立，不能证明域隔离在极端场景（如两域配置写重）下仍安全——
> 后者的防线是脚本的显式校验，不是测试。

**用例数必须填**：本次 9 项全部实际执行，无跳过。

## 已知盲区

| 盲区 | 影响面 | 缓解手段 |
|---|---|---|
| 无自动化回归 | 后续改动可能静默破坏域隔离或保护条件 | 改动后手工重跑本表九项；`audit` 的两域各一次是底线 |
| 引擎域能力名前缀靠评审 | 前缀错时归属难查，但不影响体检通过 | 在 `dev-docs/README.md` 与 `guide.md` 写明约定，评审时核对 |
| 跨域同名能力未做压力验证 | 理论上两域独立，但未实际构造同名能力做对照 | 需要时按 `new` 在两域各建一个同名能力后分别 `audit` |
| `audit` 一次只查一个域 | 交付时可能漏跑一域 | 交付清单一律要求两域各跑一次 |
