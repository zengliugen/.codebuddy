## 关键路由边界

最容易被误路由的边界场景：

1. **「检查」的宾语决定归属**：检查**环境**走本技能；检查**代码**走 `python-lint`。
   两者动词相同、宾语不同，是首要混淆源。
2. **「装」的宾语决定归属**：装工具（ruff、coverage）属本技能；装项目运行依赖
   不属本技能（项目负责人按上游流程完成）。用户说「装 ruff」时不能路由到 lint 技能。
3. **复合请求的顺序**：如「跑 ruff 报错说环境没就绪」，应先路由本技能 `ensure`，
   再回到 `python-lint` 执行检查。顺序颠倒会因为环境不存在而反复失败。
4. **环境一词的三义**：虚拟环境、运行环境、CI 环境。`description` 已限定为
   「工具环境与应用解释器」两项，其余不触发。

## 评估方法

- **人工审查**：逐条核对 `description` 是否覆盖该输入的语义，记录覆盖或遗漏。
- **盲测**：打乱 16 条用例顺序（随机种子 20261024），由独立评审者仅依据 frontmatter
  `description` 判断是否应触发，隐藏各案例所属桶后统计一致率。
- **对抗测试**：构造边界输入（「检查一下环境里的 Python 代码」「装 ruff 然后检查代码」），
  验证多意图请求的拆分是否合理、是否会在两个技能间来回摇摆。

## 结论与后续

- 当前 `description` 已显式包含两组动作词（建环境/查环境）与两个专有名词
  （工具环境、应用解释器），覆盖 ST-01 至 ST-08 全部表述。
- `python-lint` 的 `description` 内已写明「工具环境由 python-env 技能创建」，
  形成双向指认，降低 SN-01/SN-02 的误路由概率。
- 待批次二、三新增技能后重跑本评测——届时「安装依赖」「覆盖率」等词的归属会
  引入新的竞争关系。
