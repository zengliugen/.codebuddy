# python-comment 执行细则

## 一、检查步骤

```
1. 跑 ruff 的 D 系列，拿到可机械判定的问题清单
2. 逐文件读源码，评价标点是否统一、是否全中文、内容是否与代码一致
3. 合并输出：工具项 + 人工项，标注来源
4. （修复模式）逐项改写 → 复跑 ruff 确认通过
```

第一步命令：

```bash
<工具环境>/Scripts/python.exe .codebuddy/lib/python/skills/python-lint/scripts/run_ruff.py check --changed
```

> `D400`/`D415` 已在 `ignore` 中，因此 ruff **不会**报「首行标点」类问题——
> 这部分完全由本技能承担，检查时必须人工过一遍每条 docstring 的首行。

## 二、修复顺序

按「先内容后标点」的顺序，避免反复改动：

| 顺序 | 事项 | 说明 |
|------|------|------|
| 1 | 补缺失的 docstring | `D100/D101/D102/D104/D107`，结构骨架先立起来 |
| 2 | 统一标点为全角 | 首行句尾 `。`、段标题 `：`、正文与行内注释全角 |
| 3 | 补摘要与正文间空行 | `D205` |
| 4 | 充实内容 | 参数说明补约束、正文补「为什么」、声明副作用 |
| 5 | 清理死代码与冗余注释 | 被注释掉的代码删除；复述代码的注释删除 |
| 7 | 复跑 ruff | `run_ruff.py check --blocking` 必须退出 0 |

### 不要用 ruff 修首行标点

`D400`/`D415` 已在 `ignore` 中，ruff 不会碰首行标点。即使手工加回这两条做检查，
`--fix` 的修复也是**在全角句号后追加半角点**（`中断。` → `中断。.`），必须手工改。

## 三、标点规则（本项目强制全角）

| 位置 | 用什么 | 反例 |
|------|--------|------|
| 摘要行末尾 | 全角 `。` | `"""读取配置."""` |
| `Args`/`Returns`/`Raises` 的冒号 | 全角 `：` | `Args:` |
| 参数说明末尾 | 全角 `。` | `root: 项目根目录`（半角冒号 + 无结尾标点） |
| 正文叙述 | 全角 | 全段半角逗号 |
| 行内注释 | 全角 | `# 先检查,再写入` |
| 代码本体 | 半角 | `replace("\\\\", "/")` 里的符号属代码，保持半角 |

### 为什么可以直接全角

`D400`/`D415` 的判据是 ASCII 后缀匹配，无法识别 `。`——把中文句号判为「无标点」。
若强行满足这两条，就只能写半角点，造成「半角点 + 全角句号」混排（同一段 docstring
里两种句号并存）。本项目选择**全角优先、把这两条规则 ignore**：
注释一致性优先于「首行必须有标点」的工具强制。

本项目文档站为 mkdocs（只渲染 `.md`），**未使用** sphinx / napoleon / mkdocstrings，
因此全角冒号不存在「段标题被静默丢弃」的风险。

## 四、google 风格各段写法

### 摘要行

```python
"""收集符合模式的变更文件。
```

- 动词开头；全角 `。` 结尾；≤ 72 字符（中文约 36 字）。

### 正文

```python
"""收集符合模式的变更文件。

范围由项目侧配置声明，脚本不内置任何默认项：白名单为空时退回黑名单模式。
"""
```

- 与摘要空一行；说明为什么、约束、副作用。

### Args / Returns / Raises

```python
Args：
    workdir：git 命令执行目录的绝对路径。
    patterns：白名单模式清单；空列表表示退回黑名单模式。
```

- 全角冒号；每参数一行；说明含约束，不复述类型。

## 五、语言要求

**要么全中文、要么全英文，不混用。**

| 情形 | 处理 |
|------|------|
| 中文注释中夹英文描述 | 改写成中文；标识符、命令、专有名词保留原样 |
| 整段英文注释 | 改写成中文（引用外部英文原文时例外，整段保持英文） |
| 中英混排但英文是标识符 | 不判（如「调用 `run_ruff.py` 执行检查」） |

## 六、内容质量的判断要点

| 判断项 | 好 | 差 |
|--------|----|----|
| 是否说「为什么」 | 「重试三次：网络抖动时偶发超时」 | 「循环三次」 |
| 参数说明是否含约束 | 「路径，必须为绝对路径」 | 「路径」 |
| 是否声明副作用 | 「会写入缓存文件」 | 未提 |
| 是否与实现一致 | 与当前行为相符 | 描述的是旧行为 |
| 是否有信息价值 | 解释了个非显然的决定 | 复述代码字面 |

## 七、自检清单

修复完成后逐条核对：

- [ ] 所有公开模块/类/函数都有 docstring？
- [ ] 首行以**全角** `。` 结尾（不是半角 `.`）？
- [ ] 摘要与正文之间有空行？
- [ ] `Args：`/`Returns：`/`Raises：` 用**全角**冒号？
- [ ] 每个参数说明含约束，不只是名字？
- [ ] 有副作用的函数声明了副作用？
- [ ] 主动抛出的异常列在 `Raises：`？
- [ ] 全段标点统一，无「中文内容 + 半角标点」混排？
- [ ] 无中英混排（标识符除外）？
- [ ] 被注释掉的死代码已删除？
- [ ] 复跑 `ruff check` 退出 0？

## 八、边界

| 情形 | 处理 |
|------|------|
| `src/`、`tests/` 下的文件 | 不在范围（上游模板与上游基线测试） |
| 生成代码 | 跳过 |
| 注释内容本身写错了（如描述与实现不符） | 属本技能范围，判 `warning` 并给改写建议 |
| 代码逻辑有问题 | 转 `python-code-review`，不在本技能下结论 |
| 纯格式问题（行宽、import 排序） | 交 `python-lint`，本技能不报 |
| 代码字面量内的标点 | 不受本规则约束（属代码） |
