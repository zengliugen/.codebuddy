## 运行模式

`Production` —— 团队复用技能，需通过触发评估和输出风险检查。

## 核心契约

| 维度 | 定义 |
|------|------|
| 拥有的任务 | 按规范检查与修复 Python 注释（docstring 结构、全角标点、全中文、内容准确性） |
| 输出 | 检查：问题清单（位置 + 类型 + 建议）；修复：改写后的文件 + 复检结果 |
| 排除 | 不承担代码逻辑审查（属 `python-code-review`）；不重复报 ruff 已报的可机械判定项；不修改非 Python 文件 |
| 前提 | 规则 `rules/python/python-comment/` 可用；修复后复检需 `python-lint` 工具环境 |

## 两段式分工

| 段落 | 谁负责 | 内容 |
|------|--------|------|
| 可机械判定 | `ruff` 的 `D` 系列 | 有无 docstring（`D100/101/102/104/107`）、摘要与正文间空行（`D205`） |
| 需判断 | 本技能 | 标点是否统一全角、是否全中文、内容是否与代码一致、参数说明是否含约束 |

**不重复报**：ruff 已报的项不在此重复，只在其基础上评价内容。

## 标点规则（本项目强制全角）

中文注释**一律全角**：`，` `。` `；` `：` `！` `？`。

| 位置 | 用什么 |
|------|--------|
| docstring 首行句尾 | 全角 `。` |
| docstring 段标题 | 全角 `：`（`Args：` `Returns：` `Raises：`） |
| docstring 正文 | 全角 |
| `#` 行内注释 | 全角 |
| 代码本体（字符串、变量、调用） | 半角（属代码，不受本规则约束） |

**`D400`/`D415` 已加入 ruff 的 ignore**：这两条只认 ASCII 后缀、无法识别 `。`，
强行满足会让 `--fix` 产出 `中断。.` 这类混排文本。因此「首行有标点」由本技能与
自检清单保证，而非工具。

## 语言要求

**要么全中文、要么全英文，不混用**。本项目统一简体中文；标识符、命令名、专有名词按原样保留。

## 两种模式

| 模式 | 行为 |
|------|------|
| `check` | 只报告问题，不修改文件 |
| `fix` | 逐项补全或修正，改完复跑 `ruff check` 确认通过 |
