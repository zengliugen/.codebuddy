## 关键路由边界

最容易被误路由的边界场景：

1. **「规范」与「质量」的分界**：规范（格式、规则，可机械判定）走本技能；
   质量（设计、逻辑、可读性）走代码审查。用户说「检查代码」时需追问或按
   是否提到具体规则判断。
2. **「格式化」的两种含义**：代码格式（引号、缩进、换行）属本技能；
   注释格式中的**内容措辞**属注释技能，本技能只判 `D` 系列可机械判定的部分。
3. **检查范围的默认值**：不指定目标时按配置白名单展开，**不是整仓**。
   用户要求「整个项目」时必须显式传目标，否则会误以为已全量检查。
4. **check 与 fix 的授权边界**：默认 `check` 只读；`fix` 会改写文件，
   必须有明确的修改意图，不能由「检查一下」推导出「顺手改掉」。

## 评估方法

- **人工审查**：逐条核对 `description` 是否覆盖该输入的语义。
- **盲测**：打乱 16 条用例顺序（随机种子 20261025），独立评审者仅依据
  frontmatter `description` 判定，隐藏所属桶。
- **对抗测试**：构造边界输入（「把整个项目的格式都改一遍」「检查注释是否符合规范」
  「只检查我改的文件」），验证是否会越界到改写或越界到注释内容。
