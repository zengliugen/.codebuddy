# python-lint 变更记录

> **本文件由引擎仓库维护。** 本包为引擎内自建组件，正文与脚本均归本仓库所有。

## 记录规范

- 一个变更一节，**按时间倒序**，标题为 `## YYYY-MM-DD 主题`。
- 每节写明**为什么改**，而不只是改了什么——只记措辞调整的不写。
- 行为变更（脚本判定、退出码、文件产出）必须记录；纯文档润色不单独成节。

## 2026-10-30 收集清单排除已删除文件（含删除的提交会让门禁假失败）

| 项 | 内容 |
|---|---|
| 文件 | `scripts/collect_targets.py` 的 `is_deleted_entry()` 与 `main()` 过滤循环 |
| 问题 | 收集脚本只按扩展名与黑白名单过滤，未判文件是否存在。`git status` 把删除记为一条变更，路径被原样交给 ruff，得到 `E902 系统找不到指定的路径`，门禁判失败。后果是**任何含文件删除的提交都无法通过门禁**，而删除本身并没有代码可查——失败信号指向「代码有问题」，实际是「收集逻辑有问题」 |
| 补丁 | 新增 `is_deleted_entry(xy, abs_path)`，两源取并集：磁盘不存在（覆盖 ` D` / `D ` / `MD` 等全部普通删除形态）、XY 状态含 `D`（覆盖「文件仍在磁盘但已被 `git rm --cached` 移出索引」）；命中即记入 `excluded`，`reason: deleted` |
| 验证 | 临时仓库实测三种情形：已暂存删除（`D `）与未暂存删除（` D`）均被排除；`git rm --cached` 时 `D ` 被排除而同一文件的 `??` 条目仍纳入（它此刻确实是未跟踪文件）；普通修改与新增文件未被误伤。真实项目重演「删除 + 修改」链路，门禁退出码 0，不再报 E902 |

## 2026-10-29 项目根锚点去掉 .git（独立仓库形态下根定位错误）

| 项 | 内容 |
|---|---|
| 文件 | `scripts/collect_targets.py` 与 `scripts/run_ruff.py` 的 `find_project_root()` |
| 问题 | 把 `.git` 与 `.codebuddy` 并列为项目根锚点。引擎以独立 git 检出形态挂载时，向上查找会先命中 `.codebuddy` 自身，项目根误判，配置路径拼成 `.codebuddy/.codebuddy.project/...` |
| 补丁 | 两处都改为只认 `.codebuddy` 子目录作锚点，删除 `.git` 锚点判断 |
| 验证 | 模拟独立仓库形态下两处均返回真实项目根；submodule 形态下行为不变 |
