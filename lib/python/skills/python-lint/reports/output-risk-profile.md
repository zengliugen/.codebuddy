# 输出风险画像（python-lint）

## 风险矩阵

| 风险类别 | 严重度 | 概率 | 影响 | 缓解措施 |
|---------|--------|------|------|---------|
| 检查范围与预期不符（漏检） | 高 | 中 | 新增目录不在白名单内，静默漏检 | 白名单模式下清单为空时明确输出「无待检查文件」；收集脚本 `--json` 输出 excluded 及原因 |
| 带 `**/` 前缀导致误匹配 | 高 | 中 | 把 `src/extensions/` 这类同名目录也纳入检查或排除 | 模式按项目根相对路径书写；配置注释与 guide 记录实测依据 |
| 参数混用导致 format 恒定失败 | 中 | 中 | 把 `--select` 传给 `ruff format`，报 `unexpected argument`，格式检查永远不通过 | format 与 check 的参数分开构造（`build_format_args` / `build_check_args`） |
| `fix` 模式越权改写 | 高 | 低 | 用户只想检查，结果文件被改 | 默认 `check` 只读；`fix` 需显式指定；`--blocking` 内仅自动修 import 排序 |
| 巡检结果被当作全量结论 | 中 | 中 | 只检查了变更文件，被误读为整仓合规 | 报告输出实际目标清单；`--changed` 与全量在输出上可区分 |
| 工具环境缺失时静默通过 | 高 | 低 | 门禁形同虚设 | 环境缺失退出 3（非 0），不视为通过 |
| 配置缺失时回退默认值 | 中 | 低 | 规则与范围偏离项目意图 | 不内置默认值，缺键即退出 3 |
| `E501` 误报干扰判断 | 低 | 高 | 中文注释按显示宽度易超限 | `E501` 进 `ignore`，长行由 formatter 以改写方式消除 |

## 输出质量维度

### 检查结果准确性

可能的问题：
- 白名单与实际目录结构漂移（新增顶层自有目录未登记）
- 缓存目录被当作源码

防护措施：
- 范围唯一来源是 `python_lint.config`；`exclude_patterns` 已含 `__pycache__`、`.venv`、`envs`
- 收集脚本统一换算为项目根相对路径后再匹配，避免仓库前缀干扰

### 只读边界

可能的问题：
- check 被误用为修改入口
- `--blocking` 内的自动修超出预期

防护措施：
- `check` 与 `fix` 为不同模式
- `--blocking` 内只对 `I`（import 排序）自动修，属机械变换；其余仅检查
- 修复发生在暂存前（H1 位置约定），修复结果随正常暂存流程进入提交

### 结论可复现

可能的问题：
- 同一份代码两次检查结论不同

防护措施：
- ruff 版本由锁文件固定
- 规则集、行宽、风格全部来自配置，不随命令行环境变化

## 已知局限性

1. **样本量极小**：本项目被检代码仅 30 条语句（`extensions/` 与 `extensions_tests/` 合计），规则集的误报率缺乏统计意义；随着代码增长需重估 `select` 与 `ignore`。
2. **黑名单模式会静默漏审新目录**：白名单模式则要求新增顶层目录必须补登记。两种模式各有静默失败面，只能靠输出显式列出清单来缓解。
3. **不检查被检文件的注释内容质量**：只判 `D` 系列可机械判定的部分（有无 docstring、首行标点、段标题格式），措辞与准确性属注释技能。
4. **`--changed` 依赖 git 状态**：非 git 环境、或变更未反映到 `git status` 时清单为空，此时输出「无待检查文件」而非报错——需使用者知晓该语义。
5. **仅覆盖 Python**：扩展名硬编码 `.py`，其他语言不在范围。
6. **不承担语义审查**：命名是否合理、逻辑是否有缺陷、架构是否偏离项目约定，均不属本技能。
