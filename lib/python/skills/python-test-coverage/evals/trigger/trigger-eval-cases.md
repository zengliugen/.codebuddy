# 触发评测用例（python-test-coverage）

## 一、用例清单

### Should Trigger（8 条）

| 编号 | 输入 | 为何应触发 |
|------|------|-----------|
| ST-01 | 统计测试覆盖率 | 直接对应主任务 |
| ST-02 | 跑一下覆盖率 | 同义 |
| ST-03 | coverage report 看看 | 点名工具 |
| ST-04 | 扩展代码的测试覆盖情况 | 指明对象 |
| ST-05 | 这次改动有没有测试覆盖 | 变更视角 |
| ST-06 | python-test-coverage 跑一遍 | 点名技能 |
| ST-07 | 分支覆盖率多少 | 明确分支覆盖 |
| ST-08 | 测试真的跑了吗 | 正是有效性校验的诉求 |

### Should NOT Trigger（5 条）

| 编号 | 输入 | 为何不触发 | 应路由到 |
|------|------|-----------|---------|
| SN-01 | 审查这段代码 | 语义审查 | `python-code-review` |
| SN-02 | 跑一下 ruff | 静态检查 | `python-lint` |
| SN-03 | 格式化 Python 代码 | 代码格式 | `python-lint` |
| SN-04 | 建 Python 环境 | 环境管理 | `python-env` |
| SN-05 | 帮我写个单元测试 | 编写测试 | 无对应技能，直接处理 |

### Near Neighbor（3 条）

| 编号 | 输入 | 判定要点 |
|------|------|---------|
| NN-01 | 跑一下测试 | 只说跑测试，不提覆盖——不触发；若追问覆盖率则触发 |
| NN-02 | 检查注释是否规范 | 注释规范 |
| NN-03 | 代码质量如何 | 语义审查 |

## 二、关键路由边界

1. **「测试」与「覆盖率」的分界**：只说「跑测试」不触发（直接用 runner 即可）；
   提到「覆盖」才触发。
2. **ST-08 的特殊性**：「测试真的跑了吗」表面是问测试，实质是有效性质疑——
   正是本技能价值所在（全跳过仍报成功）。应触发。
3. **不承担写测试**：本技能只采集，不生成测试代码。

## 三、评估方法

- **人工审查**：逐条核对 `description` 覆盖度。
- **盲测**：乱序种子 20261028，独立评审仅依据 `description` 判定。
- **对抗测试**：边界输入「跑测试看看覆盖率」「覆盖率低是不是测试没跑」。

## 四、已知薄弱点

| 薄弱点 | 说明 | 缓解 |
|--------|------|------|
| 「测试」与「覆盖率」易混 | 用户可能认为跑测试就含覆盖率 | `description` 明确「采集覆盖率」，不含「跑测试」 |
| 有效性校验的价值不易被感知 | 用户不会主动问「测试真跑了吗」 | `description` 显式写出「全部跳过仍报成功」这一风险 |
