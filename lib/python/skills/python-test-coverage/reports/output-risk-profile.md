# 输出风险画像（python-test-coverage）

## 风险矩阵

| 风险类别 | 严重度 | 概率 | 影响 | 缓解措施 |
|---------|--------|------|------|---------|
| 用例全部跳过却报成功 | 高 | 高 | 覆盖率报 0% 被读成「代码没覆盖」，实际是测试没跑 | 断言执行数 > 0；检测 `No data was collected`；退出 3 并解释原因 |
| 用工具环境跑测试 | 高 | 中 | 缺运行依赖，用例全跳过 | 默认用应用解释器；`--tools` 需显式指定 |
| discover 静默漏测 | 高 | 中 | 缺 `__init__.py` 的子目录不被收集 | 逐文件显式传路径 |
| 覆盖率分母含测试自身 | 中 | 低 | 数字虚高 | `source` 只配被测目录，不含 `test_root` |
| 样本量极小时误读趋势 | 中 | 高 | 30 条语句基数下百分比波动 3~7 点 | 报告标注语句数；`fail_under: 0` 不设阈值 |
| 报告被清理导致无法追溯 | 低 | 中 | 无法对比历史 | 落 caches 且明确说明会清空；需要留存时另行导出 |
| ABI 不兼容导致 coverage 无法注入 | 中 | 低 | 应用环境与工具环境次版本差异过大 | 两环境均锁 3.12；实测 3.12.10 可用 3.12.14 装的 coverage |

## 输出质量维度

### 数字真实性

可能的问题：
- 测试没跑却输出 0%，与「真没覆盖」无法区分
- 分母配置错误导致百分比失真

防护措施：
- 有效性校验（执行数 > 0）在报告生成**之前**执行，不通过即中止
- 报告中同时给出执行数、跳过数与语句数，便于交叉核对

### 失败可诊断

可能的问题：
- 只报「覆盖率采集失败」，不说是环境问题还是测试失败

防护措施：
- 退出码区分：`1` 测试失败（附输出）、`3` 环境/配置/有效性失败（附原因）
- 全部跳过时明确列出总数、跳过数、实际执行数

### 可复现

可能的问题：
- 同一份代码两次采集结果不同

防护措施：
- coverage 版本由锁文件固定
- 测试收集顺序固定（按路径排序）

## 已知局限性

1. **不提供趋势对比**：报告落 caches，会被 `cleanup-caches` 清空。要看趋势需另行留存，本技能不代劳。
2. **样本量极小**：本项目 `extensions/` 仅 30 条语句，覆盖率的统计意义有限；绝对值不宜作为质量指标。
3. **只测一个测试根**：`test_root` 通常只配 `extensions_tests`。`tests/`（上游基线）不在分母内也不被采集，需用 `run_tests.ps1` 单独验证。
4. **pytest 路径未实测**：配置支持 `test_runner: pytest`，但本项目实际用 unittest；pytest 输出解析与测试收集仅按文档实现，未在真实项目验证。
5. **PYTHONPATH 注入依赖两环境 ABI 兼容**：若应用环境升级到 3.13 而工具环境仍为 3.12，coverage 的 C 扩展无法加载，此时需重建工具环境。
6. **不判定测试质量**：覆盖率高低不代表测试有效（断言是否充分不在本技能范围）。
