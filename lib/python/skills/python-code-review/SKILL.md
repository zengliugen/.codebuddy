## 运行模式

`Production` —— 团队复用技能，需通过触发评估和输出风险检查。

## 核心契约

| 维度 | 定义 |
|------|------|
| 拥有的任务 | 把「审查 Python 代码」的请求路由到 `python-code-review` Agent，并保证规则已加载、报告已落盘 |
| 输出 | Agent 审查报告（`.md` + `.json`）+ error/warning/info 计数 + 报告绝对路径 |
| 排除 | 不自己做审查判断；不检查非 Python 文件；不覆盖上游模板与上游基线测试；不承担格式检查（由 `python-lint` 的 ruff 承担） |
| 前提 | `python-code-review` Agent 可用；`python-code` 规则目录完整；`python-lint` 工具环境可选（用于格式维度复用） |

## 为什么是薄入口

审查逻辑放在 Agent 而非技能，原因有三：

1. **规则加载量**：审查要读 4 个子规则文件，塞进技能会在每次触发时占用上下文，即使不审查。
2. **可复用**：Agent 可被其他入口调度（如门禁、批量审查），技能只负责「何时触发」。
3. **职责单一**：技能管路由与落盘，Agent 管判断。

## 审查模式

| 模式 | 触发 | 输入 |
|------|------|------|
| A — Git 变更 | 「审查未提交的改动」 | `git status` + `git diff` |
| B — 单个文件 | 指定 `.py` 路径 | 读取该文件 |
| C — 目录 | 指定目录 | Glob 收集 `.py` |
| D — 代码片段 | 粘贴代码 | 对话内容 |

## 审查范围

| 范围 | 是否审查 | 理由 |
|------|---------|------|
| `extensions/**` | 是 | 项目自有运行时代码 |
| `extensions_tests/**` | 是 | 项目扩展的测试 |
| `src/**` | 否 | 上游模板，改动会被上游覆盖 |
| `tests/**` | 否 | 上游基线测试 |

## 三维度与边界

| 维度 | 归属 | 说明 |
|------|------|------|
| 代码质量与规范 | 本 Agent | 命名、类型注解、复杂度、项目约定 |
| 注释合规 | 本 Agent | 内容准确性与信息价值；可机械判定的部分由 ruff 承担 |
| 潜在 Bug 与边界 | 本 Agent | 可变默认参数、异常处理、资源释放、比较语义、并发 |
| 格式 | `python-lint`（ruff） | 工具确定性结果，Agent 直接采信、不重复报 |
| 架构 | 项目侧 `upstream-compat` 规则 | 两处判据会冲突，本 Agent 不下结论 |

## 使用边界

**不适用**：

- 只跑格式检查（用 `python-lint`）
- 解释代码在做什么（直接读代码回答）
- 非 Python 代码审查
