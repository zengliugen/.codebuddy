# 代码规范检查报告生成（format_report）

本文件说明技能内的 `scripts/format_report.py`：把 `dotnet format` 的检查日志汇总成模块化的 Markdown 报告，
用于把「检查结果」交付给团队或作为整改依据。

## 1. 适用场景

| 场景 | 说明 |
|---|---|
| 整仓代码规范体检 | 一条命令产出总览 + 模块页 + 类型汇总三件套 |
| 多解决方案合并 | 整仓与独立样例工程分别检查后，合并成一份报告（同一文件诊断自动去重） |
| 整改前基线与整改后复核 | 报告含每处诊断的行列、说明与源码，可直接对照修改 |

不适用：代码审查（语义问题见 `csharp-code-review`）、注释规范（见 `csharp-comment-checker`）。

## 2. 前置：先产生检查日志

```bash
# 整仓
python scripts/dotnet_format.py check

# 独立解决方案（如包内样例工程）
python scripts/dotnet_format.py check --project "<独立解决方案>.sln"
```

两份命令都会在 `check_logs/` 下生成 `*.log`，把路径作为 `--log` 传入报告脚本。

## 3. 生成报告

```bash
python scripts/format_report.py \
  --log <整仓日志> \
  --log <独立解决方案日志> \
  [--out <报告输出目录>] \
  [--title "代码规范检查结论"] \
  [--project-root <项目根>] \
  [--config <format_checker 配置路径>]
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `--log` | 是 | `dotnet format` 日志路径，可多次指定 |
| `--out` | 否 | 报告输出目录；**默认**为项目侧产物 `<format_checker 目录>/report_logs/<时间戳>/`（经索引 `artifacts.dirs.format_checker.check_logs` 的父目录推导） |
| `--title` | 否 | 报告标题，默认「代码规范检查结论」 |
| `--project-root` | 否 | 项目根（默认自当前目录向上查找 `.editorconfig`） |
| `--config` | 否 | `format_checker` 配置路径（默认经索引逻辑名 `format_checker.config` 定位） |

> 默认目录位于项目侧 `caches/` 下、不入库；需要交付或归档时用 `--out` 指定到目标位置（如 `Downloads` 或 `docs/`）。

退出码：`0` 成功 / `1` 执行错误 / `3` 配置缺失（项目根或配置文件不可用）。

## 4. 输出结构

```
<输出目录>/
├── 00-总览.md                     模块汇总表、行尾统计、结论、目录结构、检查范围、建议
├── 01-模块结论/                   每个模块一个文件
│   ├── Assets-Game.md
│   ├── pkg-core.md
│   └── pkg-<包>-<样例>.md
└── 02-按问题类型汇总/             横向汇总，便于同类问题一次性处理
    ├── 命名问题-IDE1006.md
    ├── 空白与布局.md
    ├── using指令.md
    └── 其他风格-IDE系列.md
```

模块页包含：结论摘要（四类问题数 / 涉及文件数 / 可否自动修复）、诊断类型分布、
各类型的「按规则汇总 + 涉及文件表 + 明细（行:列、诊断、说明、源码）」，以及自动修复命令与忽略模板。

## 5. 模块划分规则（无项目专有值）

| 路径形态 | 模块 | 文件 stem |
|---|---|---|
| `Assets/<域>/…` | `Assets/<域>` | `Assets-<域>.md` |
| `Packages/<包名>/…` | `<包名>` | `pkg-<短名>.md` |
| `Packages/<包名>/<X>~/…` | `<包名>/<X>~`（Unity 忽略目录，如样例工程） | `pkg-<短名>-<X>.md` |
| 其他 | 路径首段 | 路径替换 `/` 为 `-` |

- **短名**：对所有包名求「点分段公共前缀」后去掉，如 `com.company.framework.` + `core` → `pkg-core`；
  只有一个包时不做裁剪。
- 排序：`Assets/` 模块在前，其余按名称字母序，保证多次生成结果稳定。

## 6. 合并与去重

- 多份日志按 `(文件, 行, 列, 诊断)` 去重，保留首次出现。
- 独立解决方案的工程通常引用包源码，检查时会把包内文件重复扫一遍；去重后不会重复计数。
- 「工程数」按日志中的工程标签去重统计（无诊断的工程不出现）；「目录内 .cs」按项目配置的
  `exclude_dirs` 排除后遍历统计。

## 7. 分类口径

| 类别 | 诊断 ID |
|---|---|
| 命名问题 | `IDE1006` |
| 空白与布局 | `ENDOFLINE`、`WHITESPACE`、`IDE0055` |
| using 指令 | `IMPORTS`、`IDE0005` |
| 其他代码风格 | 其余（`IDE0017`/`IDE0047`/`IDE0048`/`IDE0049`/`IDE2000` 等） |

`ENDOFLINE` 按行计数，报告中按文件汇总（列出「共 N 行需整体转换」），不逐行列出；
其余诊断逐条列出。

## 8. 已知限制

- 只解析 `dotnet format` 的日志格式；其他工具（如 roslynator）的输出需先转成同格式。
- 源码「代码」列按日志中的绝对路径读取，日志生成后源文件被改动会导致行号偏移。
- 报告不含耗时与分工程退出码（整仓执行时 dotnet format 不逐工程计时）。
