# 命名规范化重命名（rename_symbol）

本文件说明技能内的 `scripts/rename_symbol.py`（Roslyn 重命名工具）的用途、规则来源与安全边界。
它是 `dotnet format` 的补充：**IDE1006 命名诊断无法由 dotnet format 自动修复**（重命名符号涉及语义），
本工具用于按项目根 `.editorconfig` 的命名规则批量改名并同步全部引用。

## 1. 适用场景

| 场景 | 说明 |
|---|---|
| `dotnet format` 报 IDE1006 但无法自动修复 | 缺 `s`/`m` 前缀、成员名非 PascalCase、参数非 camelCase 等 |
| 需要批量改名并更新所有引用 | 与 Visual Studio 重命名同引擎（Roslyn `Renamer`），跨工程、跨文件同步 |
| 提交前统一命名风格 | 先 `--dry-run` 出清单，确认后 `--apply` |

不适用：类型/命名空间改名、局部变量与 lambda 参数（本工具限定 member 范围）、代码审查。

## 2. 规则来源（唯一标准）

命名规则全部读取项目根 `.editorconfig` 的 `dotnet_naming_*` 三组配置，脚本与工具内**不内置任何项目前缀约定**：

| 配置组 | 作用 |
|---|---|
| `dotnet_naming_style.*` | 前缀 / 后缀 / 大小写风格 |
| `dotnet_naming_symbols.*` | 适用符号种类 / 可访问性 / 必需修饰符 |
| `dotnet_naming_rule.*` | 把符号集合绑定到样式 |

匹配优先级（与 Roslyn 行为对齐）：**必需修饰符多者优先 → `const` 优先于 `static` → 访问级别更具体者优先 → 按声明顺序**。

**只有 `severity` 为 `warning` / `error` 的规则参与改名**；`none` 与 `silent` 的规则不驱动改名（与 `dotnet format` 的 `--severity warn` 阈值一致）。因此项目把某类命名规则降级为 `none` 后，工具不会再改这类符号。

新名称生成：剥离旧前缀（含 `_` 分组下划线、以及字段前缀迁移，如 `mLock → sLock`）→ 应用大小写风格 → 拼接目标前缀/后缀。

## 3. 用法

```bash
# 试运行（默认，只输出清单，不修改文件）
python scripts/rename_symbol.py --dry-run <csproj 路径…>

# 落盘执行（修改源码并同步所有引用）
python scripts/rename_symbol.py --apply <csproj 路径…>

# 显式指定 .editorconfig（默认自 csproj 所在目录向上查找）
python scripts/rename_symbol.py --dry-run --editorconfig <路径> <csproj 路径…>

# 跳过自动构建（产物已存在时）
python scripts/rename_symbol.py --dry-run --no-build <csproj 路径…>
```

- 路径按**当前工作目录**解析，建议在项目根执行。
- 首次运行自动 `dotnet build` 工具工程（产物在 `scripts/rename_symbol/bin|obj`，已由引擎根 `.gitignore` 兜底）。
- 退出码：`0` 成功 / `1` 执行错误（含构建失败） / `2` 参数错误 / `3` 配置缺失（.editorconfig 或命名规则缺失）。

## 4. 安全边界（自动排除，无需人工筛选）

| 排除项 | 原因 |
|---|---|
| 项目配置 `exclude_dirs` 内的文件 | 三方库与生成代码（口径与 `dotnet format` 的检查范围一致，经索引 `format_checker.config` 读取） |
| 文件头含 `<auto-generated>` 的文件 | 生成代码，改名会被下次生成覆盖 |
| 单字符名称（如 `_`、`s`） | 无法推导出有意义的新名 |
| `override` 与显式接口实现 | 改名会破坏基类/接口契约 |
| 新名与已有成员重名 | 预检冲突后跳过，避免制造编译错误 |
| 非 `Ordinary` 方法 | 构造函数、运算符、访问器等不处理 |
| 带 `#pragma warning disable IDE1006` 的符号 | 抑制即视为有意豁免（按 pragma 作用域行区间判定，`restore` 后恢复；无错误码的 `disable` 视为禁用全部） |
| 带 `SuppressMessage("Style", "IDE1006…")` 的符号 | 成员级特性直接豁免；程序集级 `[assembly: SuppressMessage]` 按 `Target` 的文档注释 ID 匹配（`~E:`/`~F:`/`~P:`/`~M:` 前缀，`~` 自动去除） |

## 5. 已知限制

- **只分析传入的工程**：其引用闭包中的工程仅作为引用方被同步改写；`Assembly-CSharp` 等未加载工程中的引用不会被更新，落盘后须编译验证。
- **不改字符串字面量与注释**：若有反射、序列化或按名取值的逻辑，需人工确认。
- **Unity 工程兼容性**：`MSBuildWorkspace.TryApplyChanges` 对 Unity 生成的 csproj 不可用（空引用），工具改为逐文档写回磁盘；这也是不能直接用 Roslynator CLI 的原因。
- `word_separator` 暂未参与新名生成（仅影响词间连接符）。
- `unsafe` 修饰符不参与规则匹配（Roslyn 符号层不暴露）。

## 6. 落盘后的验证闭环

1. `git status` / `git diff` 核对改动范围，确认仅涉及预期文件。
2. 编译验证：已安装 Unity 操作类可选包时经其编译命令；未安装时用 `dotnet build`（判定见 `csharp-test/verification.mdc` §1）。
3. 复跑 `python scripts/dotnet_format.py check` 确认命名诊断清零、且未引入新的格式问题。
