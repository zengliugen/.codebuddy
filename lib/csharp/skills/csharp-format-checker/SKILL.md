## 运行模式
`Production` —— 团队复用技能，需通过触发评估和输出风险检查。

## 核心契约
| 维度 | 定义 |
|------|------|
| 拥有的任务 | 按项目根 `.editorconfig`：① 用 dotnet format 检查/修复 C# 代码格式（默认只检查不修改）；② 用 `rename_symbol.py` 按 `dotnet_naming_*` 命名规则批量重命名（IDE1006 修复，默认 dry-run）；③ 工作区行尾合规检测（`check_eol.py`）；④ 用 `format_report.py` 把检查日志汇总为模块化 Markdown 报告 |
| 输出 | 退出码（0 无格式问题 / 2 check 模式存在待格式化文件；`check_eol.py`：0 合规 / 1 有异常 / 3 配置环境不可用；`rename_symbol.py`：0 成功 / 1 执行错误 / 2 参数错误 / 3 配置缺失）+ `check_logs/` 下 `.md` 摘要与 `.log` 完整输出 + 重命名清单 + 报告目录（总览 / 模块结论 / 类型汇总） |
| 排除 | 不检查非 C# 内容、不修改配置声明的忽略目录内文件、不承担注释规范检查（见 `csharp-comment-checker`）与代码审查（见 `csharp-code-review`）；重命名只覆盖 member（字段/属性/方法/事件），不含类型与命名空间 |
| 前提 | 项目根存在 `.editorconfig`；工作区（`.slnx`/`.sln`/`.csproj`）可被 dotnet format 加载；本机 .NET SDK 可用；行尾检测另需位于 git 仓库内；重命名工具首次运行需联网还原 NuGet 包 |

## 规则文件（格式与命名标准）
本技能**不内置格式或命名规范**，唯一标准即项目根目录的 `.editorconfig` 文件：

- 检查范围仅覆盖该文件声明的文件类型（本项目为 `[*.cs]`）。
- `root = true` 使配置对项目根下全部 `.cs` 生效；如存在下级 `.editorconfig` 会被 dotnet format 自动按最近者优先合并。
- 修改 `.editorconfig` 后重新运行即可生效，无需改动技能。
- 重命名工具同样只读该文件的 `dotnet_naming_style/symbols/rule` 三组配置，不内置任何前缀约定。

### 命名规范化重命名（IDE1006）

`dotnet format` 只能报告 IDE1006、无法自动修复（重命名涉及语义），该能力由
`scripts/rename_symbol.py` 承担，执行细节见 [references/rename-symbol.md](references/rename-symbol.md)：

```bash
# 试运行：只输出待改名清单（默认）
python scripts/rename_symbol.py --dry-run <csproj 路径…>

# 落盘：改名并同步全部引用（需用户确认）
python scripts/rename_symbol.py --apply <csproj 路径…>
```

- 规则来源为项目根 `.editorconfig` 的 `dotnet_naming_*`，工具内不内置任何前缀约定。
- 仅 `severity` 为 `warning` / `error` 的规则参与改名；`none` / `silent` 的规则不驱动（与 `dotnet format` 阈值一致）。
- 自动排除：配置 `exclude_dirs` 内文件、`<auto-generated>` 文件、单字符名、`override` 与显式接口实现、重名冲突项、
  带 `#pragma warning disable IDE1006` 或 `SuppressMessage("Style", "IDE1006…")` 的符号（抑制即视为有意豁免）。
- 落盘后必须编译验证并复跑 `dotnet_format.py check`（验证闭环见参考文件 §6）。

### 检查报告生成

把检查日志汇总成交付用报告（总览 + 模块结论 + 类型汇总），执行细节见
[references/report-guide.md](references/report-guide.md)：

```bash
# 先跑检查（可多次，含独立解决方案）
python scripts/dotnet_format.py check
python scripts/dotnet_format.py check --project "<独立解决方案>.sln"

# 再汇总为报告（默认输出到项目侧 caches/.../report_logs/<时间戳>/，可用 --out 指定）
python scripts/format_report.py --log <日志1> [--log <日志2>] [--out <报告目录>]
```

- 模块按路径自动划分（`Assets/<域>`、`Packages/<包>`、`<包>/<X>~/` 独立模块），包短名由公共前缀推导，不内置项目专有值。
- 多份日志按 `(文件, 行, 列, 诊断)` 去重，独立解决方案重复扫描的包源码不会重复计数。
- `ENDOFLINE` 按文件汇总（整文件行尾统一），其余诊断逐条列出（含源码列）。
