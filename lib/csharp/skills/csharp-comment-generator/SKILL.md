# C# 代码注释生成器

调用 `csharp-comment-generator` Agent 为 C# 代码文件自动生成规范化注释。

## 功能概述
- 为缺失注释的成员（类、接口、结构体、枚举、委托、事件、方法、属性、字段、构造函数、运算符重载）生成 XML 文档注释（`///`）
- 为方法体内部的关键逻辑生成行内注释（`//`），解释"为什么这么做"
- 检查并修正已有注释的格式与内容质量问题（书写正确性、描述清晰度、描述完整性、语义一致性）
- **修正非中文注释**：遇到原有为非中文撰写的注释内容（如英文注释），将其修正为简体中文注释，技术术语可保留英文
- 为 `.cs` 文件添加文件头注释
- **读取 `csharp-comment-checker` 的 JSON 检查报告，根据精确定位逐项修复问题，实现检查→修复闭环**

## 实现约束
生成和修正注释时，**必须**遵循以下约束：

1. **LLM 驱动分析**：所有注释必须基于 LLM 对代码语义、设计意图和业务逻辑的深入分析来生成，不得使用脚本、模板或正则匹配进行机械化批量生成。
2. **禁止批量处理**：无论是对单个文件还是整个目录，均**禁止**使用脚本、批处理工具或自动化规则引擎（如正则替换、语法树模板填充等）批量生成或修改注释。每个成员的注释必须由 LLM 逐项分析并逐个生成。
3. **报告修复同理**：即使基于 `csharp-comment-checker` 的 JSON 检查报告进行修复，也必须由 LLM 逐个问题分析代码上下文后再修正，不得将报告作为批量批处理输入。

以上约束的目的是确保每条注释都能准确反映代码的真实意图和设计决策，避免机械化批量生成产生大量无意义注释。

## 职责边界
### 应触发场景

- 用户要求为 C# 文件添加、生成、补全注释
- 用户要求检查 C# 注释是否符合规范并修正
- 用户要求修正 C# 文件已有注释的格式或内容问题
- 用户提供 `csharp-comment-checker` 的检查报告（JSON），要求根据报告修复问题

### 不应触发场景

- **仅检查不修改**：需要报告而不修改代码 → 使用 [`csharp-comment-checker`](../csharp-comment-checker/SKILL.md) 技能
- **代码生成/重构**：要求编写或修改代码逻辑 → 使用通用 Agent
- **非 C# 文件**：`.ts`、`.js`、`.py` 等非 `.cs` 文件 → 本技能不支持
- **自动生成代码**：`Generated/` 或 `Gen/` 目录、含 `<auto-generated />` 标记的文件 → 豁免处理

### 与 `csharp-comment-checker` 的关系

| 维度 | `csharp-comment-generator`（本技能） | `csharp-comment-checker` |
|------|--------------------------------------|--------------------------|
| 功能 | 添加/修正注释，根据报告修复问题 | 检查注释合规性 |
| 修改代码 | 是 | 否 |
| 输出 | 修改后的源文件 | 问题报告（`.md` + `.json`） |
| 实现方式 | Agent（LLM 驱动） | Roslyn 语法树分析（确定性） |
