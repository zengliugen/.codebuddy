# 已知限制与误报场景

## 启发式规则（可能误报）

以下规则基于代码模式启发式判断，无法保证 100% 准确：

| 规则 | 默认状态 | 说明 |
|------|---------|------|
| `inline_magic_number` | 启用 (warning) | 已跳过循环条件、数组大小、case 标签、const 字段、字段初始化。跳过 0-10 范围内的小数字。但仍可能对较大字面量产生误报。建议将语义明确的数字提取为有意义的常量或枚举值。 |
| `inline_condition` | 启用 (warning) | 内置自明性过滤：字面量/null/字符串比较、0-10 小数字大小比较、单标识符判断、单层成员访问、枚举/常量比较、is 模式匹配、方法调用（方法名自述意图）均不报告；由上述自明判断组成的 `&&`/`||` 组合（如 `arg == "--json" \|\| arg == "--config"`）也不报告。仍可能对数值大小比较组合（如 `x > 100 && y < 5`）及复杂业务条件产生提示。 |
| `inline_business_rule` | 启用 (warning) | 检测比较中的字面量阈值。与 `inline_magic_number` 互补——前者关注"业务含义未知的数字"，后者关注常规字面量。 |
| `inline_performance` | 启用 (info) | 仅报告容量 >= 64 的集合预分配。 |
| `inline_algorithm` | **默认禁用** | "选择数据结构"高度依赖业务上下文，静态分析无法准确判断。如需启用，建议仅对核心算法模块使用。 |
| `inline_order` | **默认禁用** | 连续多行语句不等于顺序依赖，静态分析无法准确判断。 |
| `doc_block_comment_format` | 启用 (warning) | 检测 `/** */` 格式。多行 `///` 不受影响——每条 `///` 行均为独立的 `SingleLineDocumentationCommentTrivia`。仅整体 `/** */` 块会触发。 |

## 行内注释覆盖范围

行内注释检查目前**仅覆盖方法体**（`MethodDeclarationSyntax`）。以下成员的方法体不会被检查行内注释：

- 构造函数（`VisitConstructorDeclaration` 未调用行内检查）
- 属性访问器（`get`/`set` 块）
- 运算符重载（`VisitOperatorDeclaration` 未调用行内检查）

## 如何减少误报

1. **排除目录**：在 `comment_config.json` 的 `exclude.paths` 中添加不需要检查的目录（如 `/Tests/`、`/ThirdParty/`）。
2. **关闭特定规则**：将对应规则的 `"enabled"` 设为 `false`。例如不想检查魔法数字，将 `inline_magic_number` 的 `enabled` 设为 `false`。
3. **调整严重程度**：将高误报规则的 `severity` 从 `warning` 降级为 `info`，减少干扰。
4. **代码层面治理**：将魔法数字提取为常量/枚举值（如 `private const int MaxRetryCount = 3;`），从根源上消除误报触发源。

## 边界情况

- `#region` / `#if` 等预处理器指令前面的文档注释会被正确识别
- 属性 `[Attribute]` 前面的文档注释会被正确识别
- 指令 + 属性混合场景会被正确处理

## 技术限制

- **仅处理 `.cs` 文件**，不支持其他语言。
- **`Generated/` 或 `Gen/` 目录**下的文件以及文件头包含 `/// <auto-generated />` 标记的文件默认跳过。
- **不修改代码**：本工具仅检查和报告问题，不会修改文件。如需自动修复请使用 `csharp-comment-generator` 技能。
- **语言检测**为启发式方法，通过中文字符范围判断。技术术语白名单默认包含常见 Unity/Microsoft 术语，可通过 `comment_config.json` 的 `knownTerms` 字段按项目定制（大小写不敏感，详见 [配置文件指南](config-guide.md)）。
- **语义一致性检查**依赖 Roslyn `SemanticModel`，仅在可加载程序集引用时生效（Unity 项目通过 `Library/ScriptAssemblies/` 加载）。
- **关键字转义参数名**：参数名为 C# 关键字时，代码中须写作转义形式（如 `@object`），而 XML 文档注释的
  `<param name="...">` 必须写不带 `@` 的实际标识符（如 `name="object"`）；写 `name="@object"` 会触发编译器
  CS1572 / CS1573。本工具的 `missing_param` / `param_mismatch` / `missing_typeparam` / `typeparam_mismatch`
  规则已与编译器判定对齐：内部统一按剥离 `@` 后的标识符比对，故正确写法不再被误报，错误写法（带 `@`）会被报出。
  规范见 `.codebuddy/rules/csharp/csharp-comment/doc-comment-spec.mdc` §3.3。
