# devflow-guard 变更记录

> **本文件由引擎仓库维护。** 本包为引擎内自建技能（非上游 vendor），正文与脚本均归本仓库所有。

## 记录规范

- 一个变更一节，**按时间倒序**，标题为 `## YYYY-MM-DD 主题`。
- 每节写明**为什么改**，而不只是改了什么——只记措辞调整的不写。
- 行为变更（脚本判定、退出码、文件产出）必须记录；纯文档润色不单独成节。

## 改动前必读

1. 本技能只做**生成骨架**与**机械体检**，不修改既有文档内容——判断与措辞由人负责。
2. 脚本**不内置任何默认值**：配置缺失即退出码 3，不得为「跑通」而加内置兜底。
3. 每条告警都必须能被真实修复，否则会训练人忽略告警——不设豁免机制。
4. 改完跑 `check_manifest.py` 与 `pack_install.py status`，均须退出码 0。

## 2026-10-29 采纳写回与双向校验

上一版只在探索骨架与 `guide.md` 里写了「一旦建立能力文档，本文件冻结」，而 `audit` 完全不查。
实测：建立能力文档后把探索记录的结论改成完全相反的内容、把「已确认的决定」整行换成事后编的
理由，`audit` 仍报 0 错误 0 警告。与探索功能诞生要解决的那个问题（纪律拦不住）是同一形态。

**先确认了「本地无法禁止修改」这个前提**。摘要哈希看似能证明「没改过」，但哈希存在同一仓库，
改文件的人同样能改哈希——它只拦得住手滑，而防手滑用一次日期比较就够。因此方案不在于
「证明文件没被改」，而在于**让每次采纳由工具当场留下痕迹**，使读者不会把事后合理化误当成事前推理。

| 改动 | 为什么 |
|---|---|
| `new --from-explore` 成功后在探索记录追加 `- 采纳于：design/<名>.md（日期）` | 由工具写而非人工填：「是否被采纳、被谁采纳」必须当场留痕，人工填等于让人事后自证 |
| 新增 `check_explore_adoption`：两条反向指针 | 采纳行指向的文档必须存在（拦能力被删改名）；背景声明了来源的，记录必须有对应采纳行（拦采纳行被删）。缺任一条都留一个方向的漏洞——实测只做第一条时，删掉采纳行即可绕过 |
| 采纳写回放在登记成功之后 | 顺序颠倒的话，登记失败回滚骨架会在探索记录里留下指向不存在文档的采纳行 |
| 采纳写回失败不中止 | 骨架与登记都已完成，此时中止会留下半套状态；缺失的采纳行由 audit 兜住，可事后补 |
| 探索目录 README 去掉从未实现的「已采纳」状态行 | 状态只能表达「有没有被采纳」，无法表达「被哪个能力采纳」，而后者才是双向校验的依据。多一个状态值还会与能力状态集合混在一起 |
| `design-spec.mdc` 补「采纳之后：冻结」与「双向校验能查什么」 | 内容冻结留在规则层，与设计文档同构；同时写明不查内容回改、以及为什么不假装能查 |

**残余风险（明示而非隐藏）**：同时改探索记录内容 + 采纳行 + 设计文档引用，让两边重新一致，
本地查不出。这不是缺陷而是信息真实性的边界——能篡改工作区的人也能篡改任何校验。
真实防线是提交历史，而探索记录自称「已采纳，演进见 design/x.md」正是在提醒读者去看那份与 git。

## 2026-10-29 需求探索：把「先确认需求」变成结构

`new` 此前只校验名字格式。需求完全没成形也能建出四份骨架，而 `audit` 查得出缺字段、
查不出「全是模板话术」。也就是说「先确认需求」只是一条纪律，**没有任何机制拦**——
实测一个连名字都随口起的 `vague-thing` 照样创建成功、体检通过。

仿 openspec 的探索模式引入 `explore`：**先把判断写下来，确认后再承诺做。**

| 改动 | 为什么 |
|---|---|
| 新增 `explore <slug>` 子命令 | 探索记录可反复改写（需求本来就该变），与「一旦建立就是承诺」的能力文档分开，前者才不污染后者 |
| `new` 的 `--from-explore` 为**必填** | 三道门槛：记录存在、状态已推进、结论与「已确认的决定」非空。任一不满足即拒绝建文档 |
| `dirs.explore` 为**必需键** | 不做「默认关闭」：可选会产生两种「`new` 行为不一样」的项目，而规则文本无法同时说清两者。不需要就不该装这个包 |
| 新增 `check_explore_records` | 状态为空或不在允许集合内即报错，防止探索记录退化成空表——而它恰恰是用来防止空文档的 |

**为什么要「已确认的决定」这一节**：结论只说明最终做什么，这一节记录「凭什么这么定」。
缺它的话探索记录退化成一张结论贴纸——后来者能看到决定、看不到判据，等于把同一个问题
原样推给他重推一遍。该表同时是逐轮提问的落点：每一轮问出并拍板的决定，都在这里留一行。

**不要求使用特定诘问工具**：本族的边界是「留痕」（有决定、有判据、有前提），
「怎么问」留给项目自选。`design-spec.mdc` 给了一套逐轮提问的做法（找前沿 → 成批提问 →
记录 → 重算前沿 → 收敛），并在该处用 `pack-ref-ok` 声明「可用专门的诘问压测技能驱动」，
不点名组件、路径或命令——未安装时该段自动失效且不影响流程。

## 2026-10-29 归档后改动的处理路径

此前「已归档能力要改怎么办」在规则与脚本里都是空白，实际会退化成人手工搬文件 + 改总览表——
正是 `archive` 当初要消灭的那对手工动作，只是方向相反；而搬回活跃目录的文档写的是旧方案、
旧验收标准，已不能反映当前推理，读者会被误导。

**结论：不新增「变更机制」，改行为一律立新能力，用一根指针建立关系。**

判据不需要新造：`design-spec.mdc` 的判定表已覆盖「这次改动算不算需要文档」，
ADR 覆盖「为什么推翻原决定」，偏差记录覆盖「实际做法与预期不符」。新增一套变更文档会与这三者
逐条重合，剩下的独特内容只是一根指针。

| 改动 | 为什么 |
|---|---|
| `new` 增加 `--rework-from <已归档能力>` | 校验目标确实已归档（`archive/<名>/design.md` 存在），并在新设计文档「背景」一节写入一行来源引用。只加这一行，不复制旧内容——旧文档是「当初怎么想」的唯一记录 |
| `status` 拒绝把已归档能力改回非终态 | 原实现允许 `status <名> 草稿`，造出「状态说还在起草、位置说已完成、体检说没问题」的三方矛盾，暗示可以继续在原文档上续写 |
| 新增 `check_adr_supersede` | 原实现只校验编号连续，不校验「取代」指向的编号是否存在。指向不存在的编号时表面有链、实际断在中间，读者无从判断是笔误还是链缺失 |
| 规则与模板补「归档后不原地修改行为」 | 归档是冻结快照，不是当前事实的载体。按性质分三类：纠错可直接改，补充认知走偏差或新 ADR，改行为立新能力 |

## 2026-10-29 新增 archive 与 status，补齐四处检查盲区

体检原来只覆盖「文档是否合规」，不覆盖「文档之间的关系」。以下四处都能静默通过，一并补上。

### 新增命令

| 命令 | 为什么必须有 |
|---|---|
| `archive <能力名>` | 归档要同时移动文件与回写总览表路径。只做前者报四个「引用的文件不存在」，而后者手工最易漏、漏了的报错又看不出是归档做了一半。命令在动文件前先算完整移动计划，冲突即整体中止；移动或写表失败全部回滚；归档后统一改名，消除「按原名」与「改名」两种风格 |
| `status <能力名> <状态>` | 状态同时存在于总览表与该能力四份文档头，共五处。`audit` 不比对这两类位置（语义不同），因此「表改了文档没改」无人能发现。命令一次改全，写入前先确认所有目标文件存在 |

### 修补的盲区

| 盲区 | 后果 | 修法 |
|---|---|---|
| 总览表头写死在模板里 | 改 `overview.header` 后 `init` 产出的表头与配置不符，`new` 因 `find_table` 匹配不上而直接失败 | 模板改用 `{{overview_header}}` 占位符，由配置生成表头与对齐行 |
| 列名靠关键词硬匹配，匹配不到就静默填占位符 | 列名改成不含关键词的写法（如「方案」「排期」）时，`new` 生成的文件没有登记路径，`audit` 看到占位符照样判通过 | 抽出 `require_doc_columns`，缺列即中止并说明哪些列名不合规；`new` 与 `archive` 共用同一份映射 |
| 归档目录不受一致性检查 | 凭空出现在 `archive/` 的能力（从未登记）与「只移了一半」的归档都通过 | 新增 `check_archive_consistency`：归档目录必须对应总览表中该能力的归档路径，四类文件齐全，无无法识别的文件 |
| `adr` 把「取代」小节的 `ADR-NNNN` 也替换掉 | 新文档写成「本决策取代 ADR-00NN」——指向自己 | 只替换一级标题里的编号；残留检查不再把「取代」里的占位符判为失败 |

## 2026-10-29 新增 adr 模式，撤掉项目侧骨架副本

两件事互为前提，因此一起改。

**新增 `adr <slug>`**：ADR 没有能力命名规则，无法由 `new` 产出；而 `audit` 对「生成器」字段
是 error 级校验。于是手工建 ADR 的唯一合法方式，是一份纯手工写的文档自称由 `new` 生成——
这个荒谬的约定此前只存在于「照项目侧模板复制」这条隐性知识里。命令负责三件机器该做的事：
按现有最大编号推算下一个号（`check_adr_numbering` 要求从 0001 起连续无重复）、填日期与生成器值、
落地前自检是否残留未替换占位符。

**撤掉项目侧 `templates/`**：五份骨架不再复制到项目侧，`dirs` 少一个键，`init` 只产六个文件、
全部是说明。理由见 `guide.md` §四：副本零消费者、实例化后新鲜度无法判定、漂移无兜底、
且「复制即用」对唯一需手工建的 ADR 恰恰不成立（照抄必报生成器取值非法）。

| 改动 | 位置 |
|---|---|
| `DOC_SUBDIR_KEYS` 去掉 `templates` | `devflow_guard.py` |
| 源骨架目录 `docs/` → `skeletons/`，经 `SKELETON_DIR` 常量引用 | `references/templates/` |
| `init` 不再复制骨架，删掉副本提示 | `run_init` |
| 新增 `run_adr` 与 `next_adr_number` | `devflow_guard.py` |
| 总览 README 骨架删 `{{dir_templates}}` 行，命名规范补 `adr` 用法 | `skeletons/README.md` |
| 配置与索引删 `dirs.templates` | 项目侧 `config.json`、`project.index.json` |

## 2026-10-29 new 一并产出偏差记录

`new` 原先只产设计/计划/测试三份，偏差记录留给手工创建。但偏差与这三份同属能力级文档：
文件名由能力名派生、数量固定一份、生命周期跟着能力走。留成手工动作只多出一条
「忘了建、到体检才发现计划与偏差不成对」的路径，且在 `SCAFFOLD_SPECS` 里它本来就该在。

| 改动 | 为什么 |
|---|---|
| `SCAFFOLD_SPECS` 增加 `deviation.md` | 与其余三份同源生成，占位符、日期、生成器值一次性填好 |
| 总览表行构造补「实施偏差」列 | 原分支 `"计划" in column and "偏差" not in column` 会把偏差列落到 `dash`；产出文件后必须同时填路径，否则表与磁盘不一致 |
| 总览表「偏差」分支先于「计划」分支判定 | 两个列名都含「计划」相关判断，顺序颠倒会让偏差列匹配到计划分支 |

**空偏差记录不算违规**：模板自身写有「只有实际做法 ≠ 计划才记」的准入判据，实施顺利时
文件保持原样即可。`check_plan_deviation_pair` 只判文件是否存在（无「写明无偏差」逃生口），
因此「先建后填」比「漏建再补」更稳。

## 2026-10-28 首版交付后的缺陷修复

首版实现完成后做过两轮独立审查（结构与脚本各一轮），共修 15 项。以下按「会让功能实质失效」优先排列。

### 会让 audit 实质失效的

| 问题 | 后果 | 修法 |
|---|---|---|
| 表头提取不识别代码围栏 | 正文只贴一段模板示例、真实表缺失的文档可以完全通过 | 提取时跳过 ``` 围栏区间 |
| 归档目录不参与检查 | 归档成为「手写文档免检」的后门 | `iter_capability_docs` 递归 `archive/<能力>/` |
| 空白单元格只查部分列 | 能力列/状态列空白永不报错 | 所有列统一判空白 |
| 总览表状态列不校验 | 非法状态会让配对检查静默跳过 | 新增行状态合法性检查 |
| 同名能力重复行无检测 | 重复行语义不确定（哪个状态生效） | 新增重复检测 |

### 会产出坏文件的

| 问题 | 后果 | 修法 |
|---|---|---|
| `read_text` 用 `or ""` 兜底 | 读失败时写入 0 字节文件且退出码 0 | 返回 `(正文, 错误)`，失败即中止并回滚 |
| `init` 复制模板时替换了生成器占位符 | 项目侧模板已含合法值，手工复制即可绕过生成器校验 | 新增 `keep_generator` 参数，模板保留占位符 |
| 不替换 `<设计目录>` 等占位符 | 生成的计划文档残留字面量 | 补映射 |
| 能力名用 `re.match` | `$` 允许尾部换行，可伪造出一整行表格 | 改 `fullmatch` + 显式剔除控制字符与不可见字符 |
| `insert_row` 整文件改行尾 | CRLF 总览表被改写成 LF，产生全文件 diff | `splitlines(keepends=True)` 保留原行尾 |

### 配置与失败语义

| 问题 | 后果 | 修法 |
|---|---|---|
| 只校验键存在，不校验形状 | 空数组致 IndexError、字符串被按字符取值、负数列索引静默取错列 | 新增 `_validate_shapes`：类型、范围、互异性、去重 |
| Windows 盘符相对路径 `C:foo` | 不是绝对路径但会跳盘，`join` 后逃出项目根 | 显式拦盘符 |
| `re.compile` 只捕 `re.error` | 非字符串配置抛 TypeError 而非退出码 3 | 同时捕 TypeError，类型检查前置 |
| `run_init` 失败不回滚 | 留下半套文档结构，下次执行被冲突检查挡住 | 抽出 `_rollback`，读/写失败都回滚 |

### 检查与文档不一致

| 问题 | 修法 |
|---|---|
| `guide.md` 缺 `status_field` 键，照抄配置即退出码 3 | 骨架与键作用表都补上 |
| `guide.md` 宣称「在计划里写明无偏差可免检」，但代码未实现 | 补实现：读计划正文，「无偏差」即跳过。理由是不保留它会迫使无偏差的能力造一份空偏差文档，而空文档比没有更糟 |
| `LEVEL_INFO` 定义但从不产出，「提示档」是空转 | 新增提示项：已废弃文档仍留活跃目录 |

### 不可达代码与重复报错

| 问题 | 修法 |
|---|---|
| `new` 的回滚分支不可达（前置已校验总览表可解析） | 改为覆盖真正会失败的场景：总览表写入失败时回滚骨架 |
| 缺文件头表时同根因报两条错 | 「文件头」检查负责报，生成器检查静默跳过 |

## 一对一对应关系

本文件的条目直接对应 `scripts/devflow_guard.py` 的当前实现。改动脚本时，若改变了下表任一行所描述的行为，须同步本文件。
