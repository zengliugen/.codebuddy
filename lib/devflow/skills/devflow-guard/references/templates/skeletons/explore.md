## 既有方案调研

动手设计之前先查外面已经有什么：同类需求的成熟方案、上游或框架已有的能力、可直接复用的库。
**本节的结论是下面「已确认的决定」的事实基础**——不查就自研，要么重复实现，要么错过现成通道。

| 候选 | 来源 | 与本需求的匹配点 | 结论（采用 / 不采用 / 待验证） |
|---|---|---|---|
|  |  |  |  |

> **来源必须可追溯**：链接、库名 + 版本、或文档/源码的路径与行号；检索日期写进「更新日期」。
> 只写「网上查过」等于没查。**无法验证的标「未验证」**，不要写成事实。
>
> **确实没有匹配方案时也要留痕**：写一行「未找到匹配方案」，并在「匹配点」列写明检索范围
> 与关键词——否则无法区分「查过没有」与「没查」。
>
> **调研不等于实测**：调研负责找到候选，实测负责证明候选在本项目成立。调研通过但实测失败的，
> 记进「已排除」并写明失败的具体前提。
