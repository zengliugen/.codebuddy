# 测试策略与验收记录目录

## 放什么

| 内容 | 说明 |
|---|---|
| 测试策略 | 哪些行为必须覆盖、为什么；哪些行为刻意不测 |
| 验收记录 | 某能力上线时跑了什么、结论如何、当时的环境 |
| 已知盲区 | 测不到的行为及原因（如依赖真实设备、依赖图形环境） |

## 不放什么

**用例代码只存在于测试代码目录，本目录只引用文件名与方法名，不复制用例内容。**
用例是可执行事实，文档是判断依据；文档抄用例必然在代码改动后漂移。

## 必须区分两类测试

只要项目存在「框架基线」与「自有代码」两套测试根，结论就不可混用：

| 测试根 | 通过意味着 | 通过**不**意味着 |
|---|---|---|
| 框架基线 | 框架既有行为未被破坏 | 自有代码按预期工作 |
| 自有代码 | 自有代码按预期工作 | 框架行为完好 |

写验收记录时必须标明依据的是哪一组。文档里出现「测试全绿」而不指明测试根，等于没写。

**用例数必须记录**：测试因缺少依赖整类跳过时，框架往往仍返回成功。

## 命名

`<能力名>-testing.md`，与总览表对应。
