# 本包的本地改动索引

> **本文件由引擎仓库维护，不是上游内容。** 详细的逐条记录在 `references/cli-changelog.md`。

本包维护档位：**只读 vendor**（`packs.json` 分类 `third-party`；上游 yao-meta-skill 2.1.0）。
**只允许最小可行性补丁**——这是本包与引擎内其它**本地维护分支**包的根本差别。

## 与「本地维护分支」的区别

| 项 | 本包（只读 vendor） | 本地维护分支（引擎内另有若干） |
|---|---|---|
| 正文语言 | **保留上游原文**，不受语言规则约束 | 已中文化，受语言规则约束 |
| 可否改造 | 仅最小可行性补丁 | 允许本地改造 |
| 与上游关系 | 升级需逐项判断「上游修了没有」 | 正文以本仓库为准，无需逐字比对 |
| 为什么这样定 | 触发评估与回归测试依赖原文措辞（语义权重、测试快照），翻译会使工具链失效并导致上游拉取永久冲突 | 不产出需与上游逐字比对的评测快照，语义忠实度由本地评测保障 |

## 判断上游升级时该做什么

| 若上游…… | 则…… |
|---|---|
| 已修掉下述任一问题 | 采用上游实现，删除对应补丁，并从 `references/cli-changelog.md` 删掉那一节 |
| 尚未修 | 保留补丁，按 changelog 的「升级注意」重放 |
| 改动涉及新增文件（如 `rules/`） | 先比对职责再决定保留哪一份，避免同名规则重复注入 |

## 一条必须知道的约束

**本包的 `requires` 为空**，因此正文不得出现任何其它包的组件名——包括引擎内自建的包。
写文档或说明时点名他包技能名会触发引擎的跨包引用校验（退出码 1）。需要举例时用泛化表述。

这条踩过一次：本文件的上一版在 changelog 里直接写了某个自建包的技能名，被校验拦下。

## 维护要求

1. **改本包任何文件后，必须在 `references/cli-changelog.md` 追加一节**，写明文件、问题、补丁、边界、验证、升级注意。
2. 本文件（`PATCHES.md`）只在**改动类别或数量变化**时更新，不逐条记细节。
3. 改完跑 `python .codebuddy/scripts/check_manifest.py`，退出码必须为 0。
4. 纯文档修订（如修错别字）不需在 changelog 留节，但需在本文件对应行的「涉及范围」里体现。

## 为什么不把这些改动写进上游文件自身

`references/cli-changelog.md` 虽在包内，但它是**本仓库新增的文件**（上游无此文件），因此不构成
「改上游正文」。把说明放在这里而不是改写 `SKILL.md` 或 `README.md`，是为了让上游升级能干净地覆盖正文、
且所有本地差异集中在一处可查。
