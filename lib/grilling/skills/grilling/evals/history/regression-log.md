# 触发评测回归历史

本文件记录 grilling 技能触发面的调参迭代过程。目的是让后来者**看清这些数值是怎么来的**，避免把调参集上的 100% 误读为真实能力。

## 基线

| 项 | 值 |
|----|-----|
| 起始版本 | 上游 grilling 1.0（英文，无任何评测资产） |
| 起始评测状态 | 无 evals/，无法评测 |
| 本版版本 | 2.0.0（本地维护分支首版） |

## 迭代记录

### 第 1 轮：单概念初版（过拟合）

概念设计：仅一个 `grill_session` 概念，把「拷问 / 方案 / 压测」等全部短语塞进同一个概念。

| 数据集 | 精确率 | 召回率 |
|--------|--------|--------|
| dev | 1.000 | 1.000 |
| holdout（首测） | — | **0.200** |

**结论**：dev 满分是假象。留出集只有 20%，说明短语表在拟合用例原话。

### 第 2 轮：拆分为「动作 + 对象」

把单一概念拆为 `grill_action`（0.78）与 `review_subject`（0.22），要求动作与对象共同命中才越阈值。

| 数据集 | 精确率 | 召回率 |
|--------|--------|--------|
| dev | 1.000 | 1.000 |
| holdout | 1.000 | 1.000 |
| blind（首测） | — | **0.000** |

**结论**：新一批完全不同的表达后，召回直接归零。根因是中文无词边界——「挑一遍刺」无法匹配「挑刺」，「挨个问」无法匹配「一个个问」。

### 第 3 轮：改用组合式短语素

收录单字与双字短语素（「问」「盘」「挑」「捋」等），降低对完整短语的依赖。

| 数据集 | 精确率 | 召回率 |
|--------|--------|--------|
| dev / holdout / blind | 1.000 | 1.000 |
| acceptance（首测） | — | **0.000** |

**结论**：第三批又归零。同一方法连续三批新数据全失手，证明**问题不在短语表覆盖度，而在短语匹配方法本身**。

### 第 4 轮：继续调参至全组满分（含污染）

继续补充短语素并新增咨询服务负向概念。

| 数据集 | 精确率 | 召回率 | 是否参与调参 |
|--------|--------|--------|------------|
| dev | 1.000 | 1.000 | 是 |
| holdout | 1.000 | 1.000 | 是 |
| blind | 1.000 | 1.000 | 是 |
| acceptance | 1.000 | 1.000 | 是 |
| final | 1.000 | 1.000 | 是 |

**警告**：五组全部参与过调参，这些 100% **不构成任何准确性证明**。原设计中的 blind/acceptance/final 三组因调参过程中被查看，已丧失盲测资格。

### 第 5 轮：冻结配置后的真实盲测

配置冻结，另造一组调参全程未见的用例，**只跑一次，不迭代**。

| 数据集 | 精确率 | 召回率 |
|--------|--------|--------|
| **post_freeze** | **0.667** | **0.400** |

**结论**：这才是本技能触发评测的真实水平。

## 回归基线（自此版起算）

| 指标 | 基线值 | 判据 |
|------|--------|------|
| post_freeze 召回率 | 0.400 | 低于即视为退化 |
| post_freeze 精确率 | 0.667 | 低于 0.600 即视为退化 |

**复跑命令见 `evals/README.md` §五。**

## 方法性结论

短语匹配器适合做**回归护栏**（防止改动后大幅退化），不适合作为**触发准确率的证明**。原因：

1. 中文构词自由度高，短语素无法穷举（「挑一遍刺」「挑挑刺」「挑刺儿」）
2. 同义表达可完全不含已收录短语（「我怀疑自己漏了东西」）
3. 短短语素提高召回的同时必然带来误报（「这个设计有什么问题吗」被误判）

**真实触发质量由模型读 `description` 后判断，离线评测无法替代。**
