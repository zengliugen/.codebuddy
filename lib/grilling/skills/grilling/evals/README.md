# 触发评测说明

本文件记录 grilling 技能触发面的评测设计、数据分组与真实结论。机器证据见 [../reports/trigger_eval_evidence.json](../reports/trigger_eval_evidence.json)。

## 一、评测方法

使用 `trigger_eval.py` 的语义意图打分：把 `SKILL.md` 的 `description` 与用户输入分别映射到「正向概念」与「负向概念」的短语表，按覆盖度加权求和，超过阈值（`0.42`）判定为触发。

该方法不依赖模型推理，可离线复跑、结果确定。它的局限也很明确：**只能识别短语变体，无法理解真正的语义**——这一点在下文盲测中直接暴露。

## 二、数据分组

| 分组 | 路径 | 规模 | 用途 | 是否参与调参 |
|------|------|------|------|------------|
| dev | `evals/trigger_cases.json` | 18 | 主调参集 | 是 |

## 三、真实结论（必须如实记录）

| 分组 | 精确率 | 召回率 | 说明 |
|------|--------|--------|------|
| dev | 1.000 | 1.000 | 参与调参，数值无参考价值 |
| holdout | 1.000 | 1.000 | 参与调参，数值无参考价值 |
| blind | 1.000 | 1.000 | 参与调参，数值无参考价值 |
| acceptance | 1.000 | 1.000 | 参与调参，数值无参考价值 |
| final | 1.000 | 1.000 | 参与调参，数值无参考价值 |
| **post_freeze** | **0.667** | **0.400** | **配置冻结后的真实泛化能力** |

### 调参过程的三个阶段

1. **初版过拟合**：仅用 `grill_session` 单一概念，dev 集 100%，但第一轮留出集只有 20%——典型的短语表拟合用例原话。
2. **概念拆分**：把「动作信号」与「评审对象」拆成独立概念，避免只命中「方案」就触发。dev 与留出集回升至 100%。
3. **盲测暴露真限**：换了全新表达后立刻掉到 0/5。根因是中文无词边界——「挑一遍刺」无法匹配「挑刺」，「挨个问」无法匹配「一个个问」。改用更短的组合式短语素（单字与双字并存）后，命中率恢复，但**代价是单字短语带来误报风险**（「这个设计有什么明显问题吗」被误判为触发）。

### 结论与局限

**post_freeze 的 0.667 / 0.400 是本技能触发评测的真实水平，不应被前五组的 100% 掩盖。**

这意味着：

- 短语匹配器适合做**回归护栏**（防止改动后大幅退化），不适合作为**触发准确率的证明**。
- 真实触发质量取决于模型读 `description` 后的语义判断，本评测无法替代。
- 若后续改动 `description`，应以 `post_freeze` 分组的召回率作为回归基线，低于 0.400 即视为退化。

## 四、miss 案例分析（post_freeze）

| 输入 | 分数 | 判定 | 漏判原因 |
|------|------|------|---------|
| 我把想法说一遍，你负责找破绽 | 0.153 | 漏判 | 「找破绽」未收录；「想法」只命中评审对象 |
| Poke every hole you can find in this migration approach. | 0.153 | 漏判 | 收录了 `poke holes`，但被 `every` 隔断，无法匹配连续短语 |
| 这个存档格式的兼容性设计，我怀疑自己漏了东西 | 0.153 | 漏判 | 「怀疑自己漏了东西」是纯语义表达，无短语可锚 |
| 这个设计有什么明显问题吗 | 0.577 | 误报 | 近邻用例，单字短语「问」+「设计」叠加越过阈值 |

**这些不是可以通过再调参消除的误差**——它们反映的是短语匹配方法与自然语言之间的距离。继续调参只会让 `post_freeze` 也失去盲测意义。

## 五、复跑方式

```bash
python <yao-meta-skill>/scripts/trigger_eval.py \
  --description-file <grilling>/SKILL.md \
  --cases <grilling>/evals/post_freeze/trigger_cases_post_freeze.json \
  --semantic-config <grilling>/evals/semantic_config.json \
  --threshold 0.42
```

回归判据：`post_freeze` 的 `recall` 不低于 `0.400`，`precision` 不低于 `0.600`。
