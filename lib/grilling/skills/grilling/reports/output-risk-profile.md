# 输出风险画像

## 一、输出形态

本技能的输出不是文件、不是代码，而是**对话中的提问轮次**与**共同理解摘要**。这决定了风险性质：错误不体现为产物缺陷，而体现为**用户基于错误前提继续决策**，事后极难察觉。

## 二、风险矩阵

| 风险类别 | 严重度 | 概率 | 影响 | 缓解措施 |
|---------|--------|------|------|---------|
| 假设填充（自问自答） | 高 | 高 | 结论建在虚构前提上，用户以为已达成共识 | SKILL.md 硬约束「不自行推进」；未获回答一律视为未定 |
| 前沿越界（本轮问了下轮的问题） | 中 | 高 | 用户回答后大量返工，或回答质量下降 | 前沿判定四步规则 + 「一轮不超过两个核心决策」 |
| 事实外包（问用户可自查的信息） | 中 | 中 | 浪费用户时间，暴露未做功课，损害信任 | 明确「找事实是本技能的责任」；子代理查证 |
| 决策代劳（替用户拍板） | 高 | 中 | 用户未意识到已放弃决策权，风险后置 | 每条决策显式摆给用户，推荐答案标注为「推荐」 |
| 提前执行（未确认就动手） | 高 | 中 | 在错误方向上产生真实改动 | 结束条件三判定 + 用户确认后才执行 |
| 假收敛（把剩余问题标为不重要） | 高 | 中 | 沉默的假设残留，风险被掩盖 | 收尾必须输出「显式取舍」与「剩余风险」两节 |
| 轮次失控（问不完） | 中 | 中 | 用户失去耐心，中途放弃 | 前沿算法保证每轮都有净推进；剩余问题显式记录 |
| 摘要失真（早期决策被上下文压缩） | 中 | 低 | 深层设计树中前后决策矛盾 | 每轮摘要复述已定决策；参考 `references/project-integration.md` 已知局限 |

## 三、输出质量维度

### 3.1 问题质量

可能的问题：

- 问题过于宽泛（「你想怎么做？」），用户无法给出有效回答
- 推荐答案没有理由，用户无法定位分歧点
- 同一轮内问题数量过多，用户疲于应付
- 问题之间隐含重复，用户重复回答同一件事

防护措施：

- 每条问题必须附推荐答案，且理由须包含「该推荐成立的前提」
- 一轮问题数量受前沿算法约束，不人为设定上限但要求「不多问也不少问」
- 收尾摘要的「已定决策」逐条标注所属轮次，便于发现重复

### 3.2 轮次节奏

可能的问题：

- 一轮问太多，用户回答质量下降
- 一轮问太少，用户来回多轮失去耐心
- 未等待回答就继续推演

防护措施：

- 前沿算法天然决定每轮规模：前置条件越少、前沿越宽
- 「停下等回答」是硬约束，不是建议

### 3.3 收敛质量

可能的问题：

- 前沿未空就宣布结束
- 结束时不区分「已定决策」与「显式取舍」
- 用户确认流于形式（没有真正逐条核对）

防护措施：

- 结束三条件必须同时满足
- 摘要三段式（已定决策 / 显式取舍 / 剩余风险）
- 明确写「用户确认之后才进入执行」

## 四、执行风险

| 项 | 评估 |
|----|------|
| 脚本执行 | 无脚本，无文件写入，无网络访问 |
| 权限需求 | 仅需读取环境事实（经子代理），无写权限需求 |
| 不可逆动作 | 无。技能本身不修改任何文件 |
| 副作用边界 | 唯一的副作用是消耗对话轮次与子代理调用 |

**结论**：执行风险为低。本技能的危害面集中在「认知误导」而非「系统破坏」。

## 五、信任边界

| 边界 | 说明 |
|------|------|
| 事实来源 | 子代理查证的环境事实需可复核；无法验证的事实须标为未验证 |
| 决策归属 | 所有决策归用户，技能只提供推荐与理由 |
| 结论性质 | 共同理解摘要是「当前已确认的共识」，不是「客观正确」 |
| 适用范围 | 仅用于诘问，不用于执行；跳过诘问直接执行的请求不属于本技能 |

## 六、已知局限

1. **无法保证问全**：设计树是否完整取决于建模质量，遗漏的整片分支不会被发现。
2. **轮次深度受上下文约束**：超过五、六轮后，早期决策可能被压缩，需显式复述。
3. **触发面存在短语匹配的真限**：`post_freeze` 盲测召回仅 0.400，部分自然表达无法被识别（详见 `evals/README.md`）。
4. **不产出交付物**：用户若期待代码或文档，本技能会「问而不做」，需在开头澄清。
